# 项目介绍

> 本文回答四个问题：CCCMS 是什么、为谁而生、能做什么、核心设计理念是什么。

---

## 一、CCCMS 是什么

CCCMS 是一套**企业级中后台管理系统 / 快速开发框架**，也可直接作为二次开发底座。它由两部分组成：

| 部分 | 目录 | 说明 |
|------|------|------|
| 后端服务 | `server/` | 基于 **Webman 2.x**（Workerman 常驻内存框架）+ **think-orm** + **MySQL 8** + **Redis** |
| 管理前端 | `frontend/` | 基于 **Vue 3 + Vite + TypeScript + Element Plus + Tailwind CSS 4** |

后端采用 **插件化架构**：框架级基础能力集中在 `plugin/cccms`，业务功能一律新建业务插件，二者互不污染。

---

## 二、为谁而生

CCCMS 面向三类使用者：

- **需要一套开箱即用的后台底座**：用户 / 角色 / 部门 / 岗位 / 菜单 / 权限 / 字典 / 配置 / 日志 / 附件 / 定时任务 / 代码生成器一应俱全，装好即可开发业务。
- **需要严谨权限模型的项目**：按钮级 RBAC、角色继承，以及深入模型层的**行级 + 字段级数据权限**，适合多组织、多层级、数据需要按范围隔离的政企类系统；同一套骨架也可用**多租户**（单库共享表 + `tenant_id`，超管显式切换租户）承载多客户场景。
- **需要一个「讲规矩」的工程模板**：`fail-closed` 的鉴权、唯一声明机制、强制校验命令，把「容易漏掉的正确做法」变成编译期 / CI 能拦住的检查。

## 三、技术选型

| 层 | 技术 | 说明 |
|----|------|------|
| 运行时 | PHP >= 8.1（推荐 8.3） | 全量 `declare(strict_types=1)` |
| 后端框架 | Webman 2.x | 常驻内存，配合 `event` 扩展性能更佳 |
| ORM | think-orm 4.x | 全局查询作用域、软删除 trait、JSON 字段 |
| 数据库 | MySQL >= 8.0 | InnoDB / utf8mb4 |
| 缓存 / 会话 | Redis >= 5.0 | 验证码、登录限流、系统配置缓存、会话分界线；支持 `phpredis` 与纯 PHP 的 `predis` 双客户端 |
| 鉴权 | JWT（firebase/php-jwt） | HS256，无状态 accessToken |
| 前端框架 | Vue 3.5 | `<script setup>` + Composition API |
| 构建 | Vite 5 + TypeScript 5 | 函数式分包（vue / element-plus / echarts 三块） |
| UI 组件 | Element Plus 2.x | 中文语言包，全局 zIndex |
| 样式 | Tailwind CSS 4 | 与设计 token 打通（`--art-*` → 工具类） |
| 状态管理 | Pinia | app / user / menu / setting / worktab |
| 图表 | ECharts 5（按需引入） | 仅工作台使用 |
| 图标 | @element-plus/icons-vue | 通过名字注册表按需引用，保证 tree-shaking |
| 容器化 | Docker / Docker Compose | `php:8.3-cli-alpine` |

## 五、核心设计理念

理解下面五条，就理解了 CCCMS 与一般后台脚手架的区别。

### 5.1 fail-closed：默认拒绝，而不是默认放行

- **鉴权**：控制器方法未声明任何权限注解 → 直接 **500**（「接口未声明权限」），而不是「无注解 = 不校验」。
- **数据权限**：声明了「本部门」却没有部门 → 一条都看不到（`dept_id IN (0)`），而不是看全部；「自定义」档没有命中任何规则 → 看不到数据。
- **约束顺序**：`401 → 403 → 405 → 406`，避免越权者靠错误码探测接口结构。

> 设计说明：安全选项的默认值必须是「关」，漏配的代价是「不可用」而不是「被越权」。不可用会被立刻发现，被越权不会。

### 5.2 唯一声明机制：PHP 8 原生属性

鉴权只有一种写法 —— 控制器方法上的 `#[Permission]` / `#[NoAuth]` / `#[NoLogin]` / `#[Restrict]`，一律使用**命名参数**。没有配置文件、没有数组、没有「旧写法」。权限节点由注解扫描生成，杜绝「代码里有接口、菜单里没按钮」的漂移。

### 5.3 数据权限下沉到模型层

行级范围由 `BaseModel` 的全局查询作用域自动注入，字段级出参由 `toArray()`、入参由 `ScopedQuery` 处理。**只要查询走模型，权限就自动生效**，不依赖开发者记得手写一行。不声明又确实没有归属列的表会直接报「列不存在」——这是刻意的，逼你把语义写清楚。

### 5.4 插件化：基础与业务彻底分离

- `plugin/cccms` 只放**框架级基础功能**，禁止塞业务代码。
- 业务功能新建插件（`plugin/{name}`），提供 `db/menu.php` 即被框架自动纳管（菜单同步、权限扫描、数据权限检查、回收站类型扩展）。
- 中间件、路由、配置按插件作用域生效，互不干扰。

### 5.5 长驻内存的纪律

Webman 的 worker 是常驻进程，静态变量会跨请求存活。CCCMS 对此有三条明确约定：

| 场景 | 做法 | 原因 |
|------|------|------|
| 权限元数据（注解） | 进程内静态缓存 | 反射结果不随请求变化，reload 后自动失效 |
| 系统配置 `SysConfig` | **不用**进程内缓存，走 Redis + `flush()` | 后台改了配置必须立即生效 |
| 数据权限 scope plan | `WeakMap` 以 `UserContext` 实例为键 | 天然请求级缓存，随实例回收，不跨请求泄漏 |

> 同理，取当前用户一律用 `request()->user`，**不要**自建静态容器（非 fiber 环境下会退化为 worker 级全局，导致跨请求身份泄漏）。

## 六、与「老 CCCMS」的关系

本仓库是**全新工程**，不迁移、不兼容老的 CCCMS（ThinkPHP 8 版本）数据；鉴权体系全面改用 PHP 8 原生属性，且**只有一种声明机制**。
