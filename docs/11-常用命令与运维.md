# 常用命令与运维

> 本文汇总 CLI 命令、后台维护入口、Redis 键、系统配置项、存储、备份升级、安全加固与性能调优，供日常运维查阅。

---

## 一、CLI 命令

所有命令通过 Webman 控制台执行，路径以 `server/` 为基准。

### 1.1 `cccms:perm-scan` — 扫描权限注解 → 同步按钮节点

```bash
php webman cccms:perm-scan            # 校验 + 写库（同步 sys_menu 的 type=3 按钮节点）
php webman cccms:perm-scan --check    # 只校验不写库（CI 用）
```

- 扫描各业务插件控制器的 4 个注解，校验 5 项（必须声明注解、互斥、slug 格式、slug 唯一、Restrict 取值合法）。
- 同步策略：**只增不删**；已存在节点仅「恢复软删」+「纠正归属父节点」，**不覆盖管理员改过的 title / sort**。
- 会报告「僵尸节点」（代码里已无对应注解的按钮节点；回收站里的不算）。
- 退出码：校验有错 / 写库异常 → `1`；正常 → `0`。

### 1.2 `cccms:menu-sync` — 同步目录 / 菜单

```bash
php webman cccms:menu-sync
```

- 读取各插件的 `db/menu.php`，把目录 / 菜单（type=1/2）写入 `sys_menu`。
- `['slug' => 'xxx', 'remove' => true]` 是废弃占位：同步会连带删除该节点（含子树）与对应角色授权。
- 找不到归属父节点（声明缺失）→ 报错。
- 退出码：异常 → `1`；正常 → `0`，输出 `created / updated / removed` 与按插件明细。

### 1.3 `cccms:db-upgrade` — 增量升级表结构

```bash
php webman cccms:db-upgrade
```

- 幂等，可重复执行：补新增表 / 列 / 索引，**纠偏列默认值**（只改默认值，不动已有行数据），统一时间戳列，并执行各业务插件的 `db/schema.sql`（`SqlFileRunner`）。
- 全新安装的环境不需要执行；已有库升级时执行。
- **多租户（P2-17）升级**：已有库执行一次即可建 `sys_tenant` 表、给 12 张业务表补
  `tenant_id`（默认 `0` = 平台租户，历史数据自动归到平台）与 `idx_tenant` 索引；
  重复执行不产生变更。隔离范围与口径见 [06-数据权限 §十二](06-数据权限.md#十二多租户租户是硬边界档位是租户内的软范围)。
- **清理已下线功能的权限节点**：用户 / 数据权限规则的导入导出下线后，老库里由 `PermScanner`
  同步出来的 `sys_menu` 按钮行（`cccms:user:export|import|template`、
  `cccms:data_rule:export|import|template`）会留在授权树上。本命令**幂等**清理：查到残留才动手，
  先删 `sys_role_node` 授权记录再删 `sys_menu` 行，并 `PermissionCache::bump()` 立即失效权限缓存。
- 退出码：插件 schema 执行失败 → `1`；正常 → `0`。

### 1.4 `cccms:data-scope-check` — 校验数据权限接入

```bash
php webman cccms:data-scope-check
```

- R1：`app/controller/**` 不得出现 `Db::name` / `Db::table` / `Db::query`。
- R2：受控表必须有模型且不得声明 `$dataScope = false`；Logic 层不得裸查受控表。
- 主代码里找不到模型的受控表（如下游插件登记的 `ks_*`）只报 `NOTICE`，不计入错误。
- 退出码：存在 `error` 级 → `1`；否则 `0`。

### 1.5 `cccms:data-rule-check` — 数据权限规则体检

```bash
php webman cccms:data-rule-check
```

检查四类问题：

| 类别 | 严重度 |
|------|--------|
| `row_unsat` 行级条件互斥（命中者看不到任何数据） | 错误 |
| `field_dup` 同字段多个字段级动作 | 提示 |
| `never_hit` 取值不完整导致规则被跳过 | 提示 |
| `not_guarded` 目标表未登记受控表 | 提示 |

- 退出码：存在「条件互斥」→ `1`；无规则或仅提示项 → `0`。

### 1.6 `composer test` — 后端单元测试

```bash
cd server
composer test                 # 等价于 php tests/run.php
php tests/run.php             # 直接运行
php tests/run.php Cron        # 只跑名字包含 Cron 的用例（过滤）
```

- 零依赖运行器（`tests/run.php`），**不需要 PHPUnit**；用例在 `tests/cases/`。
- 覆盖：Cron 表达式匹配与下次运行时间、权限节点 slug 规范、CSV 编码与注入防护、数据规则体检，
  以及**集成用例**：鉴权矩阵（`AuthMatrixTest`）、数据权限三档（`DataScopeIntegrationTest`）、
  回收站 `withTrashed` 陷阱（`RecycleIntegrationTest`）。
- **需要数据库的用例在库不可用时自动跳过**，因此本地无库也能安全执行。
- 退出码：有失败 → `1`，否则 `0`。

### 1.7 `cccms:update` — 从上游仓库同步框架更新

```bash
php webman cccms:update --init                 # 首次：建立基线（记录当前代码基于的上游版本）
php webman cccms:update --check                # 只比对不写文件（CI / 预览）
php webman cccms:update                        # 同步：覆盖「本地没改过」的文件，冲突只报告
php webman cccms:update --force                # 冲突文件也覆盖（覆盖前自动备份）
php webman cccms:update --prune                # 删除上游已移除且本地未改动的文件（先备份）
php webman cccms:update --ref=v0.0.2           # 指定目标版本（分支 / tag / commit）
php webman cccms:update --source=gitee         # 指定同步源（gitee / github，默认取配置）
php webman cccms:update --tags                 # 列出远端可用版本
php webman cccms:update --status               # 只输出状态摘要（供脚本 / 监控消费）
php webman cccms:update --json                 # 机器可读输出
php webman cccms:update --no-fetch             # 离线，使用本地缓存的上游仓库
```

> 也有图形界面：后台「系统设置 → 自动升级」，提供版本切换、变更文件与行数、提交记录、
> 一键升级（与命令共用同一套实现），适合日常操作。

**解决什么**：下游基于某个版本开发业务插件后，框架自身仍在演进。本命令用
「基线 / 本地 / 上游」三方哈希比对，机械地判断哪些文件能安全覆盖，无需手工 diff。

| 分类 | 条件 | 处置 |
|------|------|------|
| 上游新增 | 上游有、本地无、基线也没有 | 直接写入 |
| 可安全覆盖 | 本地未改、上游已改 | 直接覆盖 |
| 本地已改(保留) | 本地改了、上游没动 | 保留 |
| 本地已删除(保留) | 本地删了（如重命名）、上游仍有 | 保留，不上演「复活」 |
| 冲突(需合并) | 两边都改了 | 只报告，`--force` 才覆盖 |
| 上游已移除 | 上游删了、本地未改 | 只报告，`--prune` 才删除 |

- **不碰本地独有文件**（既不在上游也不在基线里），业务插件天然安全。
- 所有覆盖 / 删除都先按原相对路径备份到 `runtime/cccms-upgrade/backups/<时间戳>/`，
  同目录下有 `report.txt`；把该目录内容按相对路径覆盖回去即可回滚。
- 不依赖本地 git 仓库：只在 `runtime/cccms-upgrade/repo/{源}` 按源缓存一份上游仓库，
  本地有无未提交改动都不影响，也不会污染本地版本历史。
- 退出码：存在未处理的「冲突(需合并)」→ `1`；正常 → `0`；执行失败（git 不可用等）→ `2`。

配置见 `plugin/cccms/config/upgrade.php`：`remotes`（同步源，可配多个镜像，如 Gitee 国内 /
GitHub 国外）、`default_source`（默认源）、`track`（跟踪分支 / tag）、`base`（基线版本）、
`exclude`（永不覆盖的路径）、`git`（可执行文件路径）。
基线记录的是**内容哈希**，与源无关，因此切换镜像不需要重建基线。
环境变量：`CCCMS_UPGRADE_SOURCE` / `CCCMS_UPGRADE_TRACK` / `CCCMS_UPGRADE_BASE` /
`CCCMS_UPGRADE_GIT` / `CCCMS_UPGRADE_ENABLE`。

**定时巡检**：内置 `UpgradeCheckTask`（`command/task/UpgradeCheckTask.php`），在后台
「定时任务」中配置即可（建议每天一次，如 `0 0 9 * * *`）。它**只比对不写文件**，
把「上游有哪些更新、几个文件需人工合并」写入执行日志，落盘永远由人显式执行。

> 首次使用前建议先给上游打 tag（`git tag -a v0.0.1 -m "..."`）；否则 `--init` 会提示
> 目标版本不存在，并回退到跟踪分支建立基线。

### 1.8 `cccms:log-archive` — 归档历史日志到对象存储

```bash
php webman cccms:log-archive                    # 归档早于配置天数的日志
php webman cccms:log-archive --dry-run          # 只统计，不落盘不删除
php webman cccms:log-archive --days=30 --batch=1000
php webman cccms:log-archive --path=/auth/login # 只归档登录日志
```

- **破坏性操作**：把选中的 `sys_log` 记录序列化为 JSONL(gzip) 上传到对象存储，**上传成功后**再按
  `id` 删除主库记录（先存后删，绝不出现「删了没存」）；按批执行，天然可重入。
- 归档前对 `params` / `result` 二次脱敏（复用 `LogRedactor`，与操作日志中间件同一份规则）。
- 与内置任务「清理历史日志」（`LogCleanTask`，直接删）的区别：本命令先把冷数据存下来，
  适合长期留存 / 合规审计。
- `--days` 有硬性下限 `7`（避免误删），`--batch` 收敛到 `[1, 50000]`。
- 退出码：失败（存储不可用等）→ `1`；正常 → `0`。

配置见 `plugin/cccms/config/log.php` 的 `archive` 段：

| 键 | 默认 | 环境变量 | 说明 |
|----|------|----------|------|
| `days` | `30` | `LOG_ARCHIVE_DAYS` | 归档「创建时间早于 N 天」的记录 |
| `batch` | `1000` | `LOG_ARCHIVE_BATCH` | 每批条数 |
| `driver` | 空 | `LOG_ARCHIVE_DRIVER` | 存储驱动；留空 = 跟随 `upload.storage_driver` |
| `path` | `log-archive` | `LOG_ARCHIVE_PATH` | 对象存储路径前缀 |

**定时归档**：`db/seed.sql` 已预置任务「日志归档到对象存储」（`0 0 4 * * *` → `LogArchiveTask`），
**默认停用**（`status = 0`）—— 归档会删主库数据，确认对象存储可用后再手动启用。

## 二、后台维护入口

右上角用户下拉里的「**系统同步 / 清理缓存**」分组（权限节点 `cccms:config:refresh`）与 CLI **共用同一份实现**：

| 范围 | 行为 |
|------|------|
| `menu` | `MenuSyncer::syncAll()` |
| `perm` | `PermScanner` 扫描 + 校验（有错整批不写库） |
| `schema` | 执行各插件 `db/schema.sql` |
| `cache` | `SysConfig::flush()` + `PermissionMeta::flush()` |
| `all` | 以上全部 |

接口：`POST /system/refresh`。同步完前端会自动重挂动态路由并刷新当前用户权限。

## 三、启动 / 停止 / 重载

```bash
# Linux / macOS
php start.php start        # 前台运行（调试）
php start.php start -d     # 后台守护
php start.php status       # 查看进程状态
php start.php reload       # 平滑重载（改 PHP 代码后）
php start.php restart      # 重启
php start.php stop         # 停止

# Windows（无自定义进程，定时任务不生效）
php windows.php
```

- 默认监听 `0.0.0.0:8787`（`server/config/process.php`）。
- 开发环境 `Monitor` 进程在 Linux 下会自动监控 `app/`、`plugin/*/app`、`plugin/*/config` 等目录，文件变更热重载。
- 进程数 `cpu_count() * 4`；`crontab` 调度进程固定 `count = 1`。

## 四、Redis 键说明

| 键 | 用途 | TTL |
|----|------|-----|
| `cccms:config:all` | `SysConfig` 全量配置缓存 | 300s（保存后 `flush()` 立即失效） |
| `cccms:auth:ver` | 权限缓存**版本号**（只增不减） | 永久（`PermissionCache::bump()` +1） |
| `cccms:auth:ctx:{版本}:{用户ID}` | 角色 + 权限集合缓存 | 300s |
| `cccms:dict:ver` | 字典缓存**版本号**（只增不减） | 永久（`DictCache::bump()` +1） |
| `cccms:dict:d:{版本}:{字典类型ID}` | 字典数据缓存（按 `type_id`） | 600s |
| `cccms:captcha:{id}` | 图形验证码答案（**一次性**，校验后即删） | 300s |
| `cccms:login_fail:user:{用户名}` | 登录失败计数（**账号维度**，达阈值锁定该账号） | `security.login_fail_window` |
| `cccms:login_fail:ip:{IP}` | 登录失败计数（**IP 维度**，达阈值只限流该 IP、不锁账号） | `security.login_fail_window` |
| `cccms:rate:{用户ID}:{路径}` | 接口限流固定窗口计数（每用户每路由） | `security.rate_limit_window` |
| `cccms:session:min_iat` | 全局会话分界线（维护模式踢非超管） | `security.token_ttl` |
| `cccms:token:bl:{jti}` | 单令牌黑名单（登出） | 令牌剩余有效期 |
| `cccms:token:cut:{用户ID}` | 用户级令牌分界线（强制下线） | `security.token_ttl` |
| `cccms:online:s:{jti}` | 在线会话明细（用户 / IP / UA / 时间） | `security.token_ttl` |
| `cccms:online:index` | 在线会话索引（ZSet，按最后活跃排序） | 无 TTL，惰性清理 |

> 另有定时任务调度去重的秒级键（`CronMatcher::markAndCheckHit`），会自动清理 2 分钟前的记录。

**手工排查技巧**：

```bash
redis-cli keys 'cccms:*'                  # 看当前缓存键
redis-cli get cccms:auth:ver              # 权限缓存版本号
redis-cli del cccms:config:all            # 手工清配置缓存（等价于后台「清理缓存」的一半）
redis-cli keys 'cccms:online:s:*'         # 在线会话明细
```

> 权限缓存不想逐个删：让 `cccms:auth:ver` **+1** 即可（旧键自然过期），
> 或直接在后台点「清理缓存」。字典缓存同理 —— 让 `cccms:dict:ver` **+1**（字典的增删改
> 与回收站还原 / 彻底删除已自动 bump，一般无需手工干预）。

Redis 客户端：装了 phpredis 扩展就用扩展，否则回退 `predis/predis`（`server/config/redis.php`）。

## 五、系统配置项清单

`sys_config` 种子内置 **5 组 32 项**，全部已接入实际逻辑（保存后立即生效）。读取用 `SysConfig`。

### 5.1 系统（`system.*`）

| 键 | 生效位置 |
|----|----------|
| `system.name` / `system.logo` / `system.icp` / `system.copyright` | 站点品牌与页脚（`GET /config/ui`） |
| `system.maintenance` / `system.maintenance_notice` | 维护模式（非超管立即失效 + 503 + 无法登录） |

### 5.2 界面（`ui.*`）

| 键 | 生效位置 |
|----|----------|
| `ui.theme_mode` / `ui.theme_primary` | 前端默认主题与主色 |
| `ui.page_size` | 列表默认分页条数 |
| `ui.tags_view` | 是否显示多标签页 |
| `ui.container_width` | 内容区最大宽度（0 = 占满） |

> 前端用户偏好存 `localStorage['cccms_theme']`；后台 `ui.*` 仅在用户**没有本机偏好**时作为默认。

### 5.3 安全（`security.*`）

| 键 | 生效位置 |
|----|----------|
| `security.login_captcha` | 登录验证码开关 |
| `security.login_fail_limit` / `security.login_fail_ip_limit` / `security.login_fail_window` | 登录失败锁定：账号维度次数 / 同 IP 维度次数 / 窗口时长 |
| `security.token_ttl` | 令牌有效期（秒，默认 2 小时）；剩余不足 1/3 时自动滑动续期（`X-Refresh-Token`），活跃用户不掉线 |
| `security.password_min_length` | 密码最小长度（新增、编辑、重置密码与个人改密共用） |
| `security.password_max_length` | 密码最大长度（默认为 64，避免超长口令放大 bcrypt 开销） |
| `security.password_strength` | 需包含的字符类别数（大写/小写/数字/符号）；内置弱口令黑名单与「不得包含用户名等身份信息」始终生效，无开关 |
| `security.rate_limit_enable` | 接口限流开关（`RateLimit` 中间件） |
| `security.rate_limit_limit` / `security.rate_limit_heavy_limit` / `security.rate_limit_window` | 普通接口次数 / 重接口（export·import·generate）次数 / 窗口秒数 |

### 5.4 上传（`upload.*`）

| 键 | 生效位置 |
|----|----------|
| `upload.max_size` | 单文件上限（MB） |
| `upload.ext_allow` / `upload.image_ext` | 允许扩展名 / 视为图片的扩展名 |
| `upload.storage_driver` | 存储驱动（local / oss / cos / qiniu） |
| `upload.url_prefix` | 访问前缀（切 CDN 改这里） |
| `upload.oss_*` | 阿里云 OSS 凭证（access_key_id / access_key_secret / bucket / endpoint / domain） |
| `upload.cos_*` | 腾讯云 COS 凭证（secret_id / secret_key / bucket / region / domain） |
| `upload.qiniu_*` | 七牛云 Kodo 凭证（access_key / secret_key / bucket / domain） |

云存储凭证**只在后台配置**（`config/filesystem.php` 已不含凭证）：配置页按 `upload.storage_driver`
只显示当前驱动对应的字段，来回切换驱动不会清空已填的其它驱动配置；密钥类项（`*_secret` / `*_secret_key`）
以 `enc:` + Cipher 密文存库，列表接口只回传「是否已配置」，**留空提交 = 保持原值不变**。
凭证读取走 `SysConfig`，后台保存后立即生效，无需重启。

### 5.5 日志（`log.*`）

| 键 | 生效位置 |
|----|----------|
| `log.keep_days` / `log.auto_clean` | 历史日志保留天数 / 自动清理开关（被内置任务 `LogCleanTask` 读取） |
| `log.record_read` | 是否记录 GET 查询操作 |
| `log.slow_threshold` | 慢接口告警阈值（毫秒，默认 3000，`0` = 关闭）；超过时额外写 `runtime/logs/slow.log` |

**新增配置项**：`db/seed.sql` 加一行 + 消费处调用 `SysConfig::getInt/getBool/getString/getList('your.key', 默认值)`。

## 六、存储与附件

### 6.1 驱动

`StorageManager` 支持 `local` / `oss` / `cos` / `qiniu` 四种驱动，统一接口 `upload / url / delete`，统一结果结构 `{path, name, original_name, url, size, mime, ext, hash}`。

| 驱动 | 依赖 | URL 逻辑 |
|------|------|----------|
| `local` | 无 | `upload.url_prefix`（默认 `/storage`）；落盘 `public/storage/Ymd/` |
| `oss` | `aliyuncs/oss-sdk-php` | `domain` 优先，否则 endpoint/bucket |
| `cos` | `qcloud/cos-sdk-v5` | `domain` 优先，否则 `https://{bucket}.cos.{region}.myqcloud.com` |
| `qiniu` | `qiniu/php-sdk` | `domain` 前缀 |

云存储 SDK **按需安装**：未安装时抛 500 并提示 composer 命令。

凭证（AccessKey / Secret / Bucket / Endpoint / Region / 域名）在后台「配置管理 → 上传」维护，
见 [§5.4](#54-上传upload)。驱动名与 `SysConfig::getString('upload.storage_driver')` 一一对应，
**未配置或配置不全时抛 500 并提示缺哪几项**（不会静默回落到 local）。

### 6.2 安全

- 上传：扩展名白名单 + 大小上限（默认 10MB）+ **随机重命名**（不使用原始文件名）。
- 本地驱动 `delete` 用 `realpath` 校验**防目录穿越**，只删 `public/storage` 内文件。
- **`public/storage` 必须禁止解析 PHP**（硬要求），或直接切独立域名 / CDN。

### 6.3 切换存储后端

切换前务必注意：**`FileStorage::url()` 使用当前驱动生成 URL，切换后历史数据不会自动迁移**。切换建议：

1. 先迁移历史文件到新后端；
2. 在「配置管理 → 上传」把驱动切到目标值，页面随切换展开该驱动的凭证项，填好并保存；
3. 用 `upload.url_prefix` / 该驱动的 `domain` 指向新地址。

## 八、安全加固清单

| # | 项 | 说明 |
|---|----|------|
| 1 | 替换 `JWT_SECRET` | HS256 要求 >= 32 字节，随机生成 |
| 2 | 替换 `DATA_ENCRYPT_KEY` | 改动后历史加密字段无法解密，**不做密钥轮换** |
| 3 | 关闭 debug | 不要设置 `APP_DEBUG=true`（**默认即关闭**，由环境变量控制） |
| 4 | 数据库最小权限 | 不要用 `root` |
| 5 | `public/storage` 禁 PHP 解析 | 或切独立域名 / 云存储 |
| 6 | 开启登录验证码 | `security.login_captcha = 1` |
| 7 | 调整失败锁定阈值 | `security.login_fail_limit` / `security.login_fail_window` |
| 8 | 提高密码长度下限 | `security.password_min_length` |
| 9 | 缩短令牌有效期 | `security.token_ttl`（默认已为 2 小时；调大即扩大 XSS 有效窗口，体验由滑动续期兜住） |
| 10 | 删除 / 改密默认账号 | `admin / admin123` 上线即改 |
| 11 | Nginx 层限流 | 对 `/auth/login` 做 IP 维度限流 |
| 12 | 开启 HTTPS | 前端与后端统一经 HTTPS |
| 13 | 运行时目录权限 | `runtime/`、`public/storage/` 可写，其余只读 |
| 14 | 数据权限接入检查 | 把 `data-scope-check` / `data-rule-check` 接入 CI |

## 十一、CI 与质量门禁

### 11.1 后端（`.github/workflows/php.yml`）

触发条件：`server/**` 或该工作流本身变更时（push / PR 到 `main`）。

| 步骤 | 内容 |
|------|------|
| 环境 | PHP 8.3 + 扩展 `pdo` / `pdo_mysql` / `pcntl` / `redis` / `mbstring` |
| 服务 | `mysql:8.0` + `redis:7-alpine`（带健康检查） |
| 依赖 | 缓存 `server/vendor`；`composer validate --no-check-publish` + `composer install` |
| 初始化 | 导入 `db/schema.sql` 与 `db/seed.sql` |
| 同步 | `cccms:menu-sync` + `cccms:perm-scan` |
| 门禁 | `cccms:perm-scan --check` → `cccms:data-scope-check` → `cccms:data-rule-check` |
| 测试 | `composer test` |

> `composer validate` **故意不加 `--strict`**：`composer.json` 继承自 webman 模板，
> 空 PSR-4 前缀（`"": "./"`，用于插件自动加载）会被 `--strict` 判为警告而非错误。

### 11.2 前端（`.github/workflows/frontend.yml`）

触发条件：`frontend/**` 或该工作流本身变更时。

| 步骤 | 内容 |
|------|------|
| 环境 | Node 20 + npm 缓存（`frontend/package-lock.json`） |
| 依赖 | `npm ci` |
| 门禁 | `npm run format:check` → `npm run lint` → `npm run i18n:check` → `npm run build`（含 `vue-tsc --noEmit`） |

> `npm run i18n:check`（`scripts/check-i18n.mjs`）用 esbuild 编译语言包后比对 `zh-CN` / `en-US`
> 的命名空间与 key 集合，**不一致直接失败**；另会列出仍有硬编码中文的非注释行，仅提示不影响结果。

### 11.3 本地等价命令

```bash
# 后端
cd server
composer validate --no-check-publish
php webman cccms:perm-scan --check
php webman cccms:data-scope-check
php webman cccms:data-rule-check
composer test

# 前端
cd frontend
npm run format:check && npm run lint && npm run i18n:check && npm run build
```
