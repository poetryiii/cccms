## 分类口径

| 分类 | 用于 | 问题内容写什么 | 修复内容写什么 |
|------|------|----------------|----------------|
| 安全 | 漏洞、暴露面、权限收口 | 原风险与触发条件 | 拦截点、生效前提 |
| 新增 | 新能力 / 新接口 / 新页面 | 原来缺什么、痛在哪 | 落地形态与边界 |
| 变更 | 既有行为、结构、默认值调整 | 原行为 | 新行为 + 存量兼容动作 |
| 修复 | 缺陷 | 现象 + 根因 | 改了哪几处 |
| 移除 | 下线能力 / 删代码 | 为什么留不住 | 删了什么 + 存量怎么清 |
| 性能与可观测 | 缓存、索引、指标、探活 | 原瓶颈或盲区 | 实现要点 |
| 工程化 | CI、静态分析、测试、构建、脚本 | 原缺口 | 接入方式 |
| 文档 | docs 与代码同步 | 原漂移点 | 补了哪篇 |

## 附录 · 明确不做

> 本节是**决策留档**：不做项一律记在这里，避免反复讨论；需求变化时先改本节写明新决策，再动工。
> 最后复核：2026-10-23。

| 事项 | 原因 |
|------|------|
| 前端 E2E（Playwright）、UI 自动化基线 | 用例随 UI 变动长期维护的成本高于收益；主链路回归由后端集成测试 + `lint` / `build` 覆盖 |
| 多因素认证 TOTP | 现有「口令策略 + 登录限流 + 图形验证码 + 2h 令牌 + 滑动续期」已覆盖，收益与改造量不成比 |
| 导入导出增强 | 用户 / 规则导入导出已下线，仅保留日志导出，不再扩展 |
| 连续失败升级为强制验证码 | 需前端登录页联动改造，成本高于收益 |
| 后端解密 + 按数据权限 mask 下发 | 改造量 5 pd+，`decryptField` 与 `cryptoKey` 目前无调用方 |
| HttpOnly 刷新令牌 | 需服务端 refresh 接口 + CSRF 防护，5 pd+；现有短 TTL + 滑动续期已缓解 XSS 面 |
| 密钥轮换（`data_encrypt_key`） | 历史加密字段将无法解密，轮换须先设计密文版本号方案 |
| 兼容老 CCCMS（ThinkPHP 8）数据 | 本仓库为全新工程 |
| 在 `plugin/cccms` 内放业务功能 | 基础与业务必须分离，业务一律新建插件 |
| `sys_config` / 关联表 / 日志的软删除 | 配置无归属、日志按天数清理 |
| ~~站内消息实时推送（WebSocket / SSE）~~ **两条通道均已实现** | 2026-10-23 交付 SSE 通道（独立进程 + Redis 事件总线 + `useRealtime()`）与 WebSocket 通道（`process/Websocket.php`，复用同一事件源与事件语义），见 [07-功能模块 §27](07-功能模块/03-扩展能力.md#二十七实时推送realtime--f9sse--websocket-双通道)；双向通道暂无业务场景，仅在需要客户端上行时用 `VITE_REALTIME_DRIVER=ws` 开启 |
| SSO 单点登录（OIDC / 企微 / 钉钉 / 飞书） | 单个 provider 3~5 pd 且需长期回归，现有账号密码链路已闭环 |
| 工作流引擎（轻量审批流） | 产品级模块，15 pd 起步，暂无落地场景 |
| 数据权限铺开到 `post` / `notice` / `dict_*` | 这些表本质是全局共享配置，加行级范围会让管理员看不到自己建的数据 |
| 前端骨架屏 | 路由切换已有 NProgress，hash 路由 + keep-alive 下白屏窗口很短 |
| 云存储直传（预签名 / STS） | 需逐驱动实现签名与前端改造；分片上传已覆盖大文件与断点续传 |
| 附件私有化 + 预签名下载 | 需签名接口 + 时效控制 + 前端全量替换 URL（4~6 pd），仅合规场景才值得 |
| API 签名防重放（timestamp + nonce + sign） | 已有 HTTPS + 短 TTL JWT + 全站限流 + `jti` 黑名单 |
| 密码历史校验 / 首次登录强制改密 / 密码过期 | 无对应场景；NIST SP 800-63B 亦不推荐强制定期改密 |
| 数据库连接池 / 断线重连自研 | 属 `think-orm` 框架层职责，且无实证断连问题 |
| P1-1 插件表租户化 · 方案 A（插件骨架默认 `tenant_id` + `$tenantScope = true`） | 方案 B 已落地：`cccms:data-scope-check` 的 R3 强制插件表「登记受控表 / 自带 `tenant_id` / 显式豁免」，把「忘配」从静默放行变成退出码 1。方案 A 需改插件生成骨架并迁移存量插件表（3~5 pd），收益仅剩「默认更安全」一档，与存量数据风险不成比；新插件接入时按 R3 显式声明即可 |
| R-12 开发依赖告警（tinypool / esbuild / @vitest/mocker） | 三者全在开发依赖树，`npm audit --omit=dev --audit-level=high` 为 0 漏洞；唯一修复路径是把 vitest 升到 4（breaking），需回归 9 个测试文件 / 96 条用例。`tinypool` 仅在跑测试进程时可达，不暴露给最终用户；与「Vite 大版本升级」合并评估，不再单独跟踪 |
| P2-11 性能基线与压测沉淀 | 属部署 / 运维动作：脚本 [`server/loadtest/baseline.js`](../server/loadtest/baseline.js) 已就绪，剩余是「目标数据量 + 目标硬件」的实测记录。基线随环境变化，不宜作为代码待办长期挂在计划里；实测数据直接填入 [11-常用命令与运维 §9.1](11-常用命令与运维/03-运维与门禁.md#91-性能基线p2-11) 的表格 |
| P2-3 生产环境接入真实网关（SMTP / 短信） | 代码侧适配器、验证码与限流已就绪，剩余是在 `sys_config` 填服务商参数并验证送达，属上线前部署配置动作；按 [02-安装部署 §4.6](02-安装部署.md#46-接入找回密码真实网关p2-3上线前必配) 执行，不再作为开发待办 |
| F7 CMS 内容模块 / F8 前台会员体系（`plugin/cccms_cms` / `plugin/cccms_member`） | 2026-10-23 评估后放弃：后端主体已成型，但缺内容模型、栏目级数据权限（两模型显式 `$dataScope = false`）、会员找回密码、独立会话索引/登录设备，且会员侧没有任何前端页面；补齐成本高于收益，决定不纳入产品范围。相关代码、语言包、前端页面、库表（`cms_category` / `cms_content` / `member` / `member_level` / `member_points_log`）、菜单与权限节点已全部回滚（未发布过，故不计入变更清单）。`CheckLogin` 保留对 `aud = member` 历史令牌的拦截 |
