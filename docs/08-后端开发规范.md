# 后端开发规范

> 本文是后端开发的**必守约定**：分层职责、命名、代码风格、数据访问规则、异常处理，以及「新增接口 / 新增插件」的标准步骤与提交前检查清单。

---

## 一、分层职责

```
Controller  →  Logic  →  Model
   薄           厚         薄
```

| 层 | 目录 | 职责 | 明确禁止 |
|----|------|------|----------|
| **Controller** | `app/controller/` | 解析请求、声明权限注解、调用 Logic、`return $this->ok(...)` | ❌ 写业务逻辑 ❌ 直连数据库 |
| **Logic** | `app/logic/` | 业务规则、校验、事务、编排；**数据访问唯一收口** | ❌ 感知 HTTP（不读 `Request`） |
| **Model** | `app/model/` | 表结构映射、数据权限声明、软删除 / 时间戳 | ❌ 写业务分支 |
| **support** | `support/` | 框架级基础设施（可直查库） | ❌ 放业务逻辑 |

> **控制器直连数据库会被 `cccms:data-scope-check` 直接拦下**（R1），因为那等于悄悄关掉数据权限。

---

## 二、命名与文件

| 对象 | 规范 | 示例 |
|------|------|------|
| 命名空间 | `plugin\{插件}\{子目录}` | `plugin\cccms\app\logic` |
| 控制器 | `{模块}Controller.php` | `UserController.php` |
| 逻辑层 | `{模块}Logic.php`，`final class`，方法 `static` | `UserLogic.php` |
| 模型 | 单数大驼峰 | `User.php`、`CrontabLog.php` |
| 表名 | 模型 `$name` 省略 `sys_` 前缀 | `protected $name = 'user';` |
| 权限节点 | `{插件}:{模块}:{动作}` | `cccms:user:save` |

---

## 三、PHP 代码风格

每个 PHP 文件头部：

```php
<?php

declare(strict_types=1);

namespace plugin\cccms\app\logic;
```

约定：

- 全部开启 `declare(strict_types=1)`。
- 类的 PHPDoc 写明**职责边界**与**关键设计原因**（尤其是有意为之的反直觉行为）。
- Logic / support 工具类用 `final class`；方法能 `static` 就 `static`。
- 类型尽可能显式（参数、返回值、数组形状用 PHPDoc `@param array{...}` / `@return array<int,array{...}>`）。
- 抛业务错误统一 `throw new ApiException('消息', code)`；不要 `return ['code' => ...]`。
- JSON 字段用 ORM 的 JSON 类型（`protected $json = ['params'];`），**不要逗号字符串拼接**。
- 时间戳交给数据库默认值（`$autoWriteTimestamp = 'datetime'`），业务层不手写 `date()`。
- 数组键顺序、导入顺序（`use` 按字母序）保持一致。

## 四、控制器规范

```php
#[Permission(slug: 'cccms:user:save', title: '用户保存')]
#[Restrict(methods: ['POST'])]
public function save(Request $request): Response
{
    return $this->ok(UserLogic::create($request->all(), $request->user));
}
```

- 必须继承 `plugin\cccms\basic\BaseController`。
- **必须声明权限注解**（否则 500，fail-closed）。
- 写操作补 `#[Restrict(methods: ['POST'])]`。
- 给 `#[Permission]` / `#[NoAuth]` / `#[NoLogin]` 写 `title`，它会作为操作日志的操作名。
- 只做「取参 → 调 Logic → 返回」，不写分支判断。
- 新增方法后**记得在 `config/route.php` 注册路由**（默认路由已禁用）。

## 五、Logic 规范

```php
final class UserLogic
{
    /** 可写字段白名单 */
    private const FIELDS = ['username', 'nickname', 'email', 'phone', 'status'];

    public static function create(array $data, UserContext $user): array
    {
        PasswordPolicy::assertValid((string)($data['password'] ?? ''));
        // ...
        return ['id' => $id];
    }
}
```

- **数据访问一律走模型**（`User::where(...)`），尽量避免 `Db::name()`。
- 确实需要查询构造器（跨表聚合、原生 SQL、元数据反射）时，注意：
  - 软删场景用 `SoftDelete::apply()` / `onlyTrashed()`；
  - 涉及**受控表**的裸查询会被 `data-scope-check` 报错，应改模型。
- 字段白名单显式列出，不整体 `$data` 落库。
- 唯一性 / 存在性校验用 `withoutGlobalScope()`（看全量），回收站占用一并检查（`withTrashed()`）。
- 单条读写入口统一 `assertInScope()`：越权 403、不存在 404。
- 事务用 think-orm 的 `Db::transaction()`。

## 六、模型规范

```php
final class User extends BaseModel
{
    protected $name = 'user';
    protected $hidden = ['password'];

    /** 数据权限：仅本人 = 自己这个账号；本部门经 sys_user_dept */
    protected $dataScope = [
        'owner' => 'id',
        'dept'  => [self::class, 'deptScope'],
    ];

    public static function deptScope($query, array $deptIds): void
    {
        $userIds = UserDept::whereIn('dept_id', $deptIds)->column('user_id');
        $userIds ? $query->whereIn('id', $userIds) : $query->whereRaw('1 = 0');
    }
}
```

必守：

| 项 | 约定 |
|----|------|
| 表名 | `protected $name = 'user';`（无 `sys_` 前缀） |
| 软删 | 有 `delete_time` 的什么都不用做；**没有的必须** `protected $deleteTime = false;` |
| 时间戳 | 没有 `update_time` 的模型声明 `protected $updateTime = false;`；纯关联表声明 `protected $autoWriteTimestamp = false;` |
| JSON 列 | `protected $json = ['dept_ids'];` |
| 数据权限 | 参与就声明语义；**不参与必须显式** `protected $dataScope = false;` |

> ⚠️ **陷阱**：模型参与数据权限但表没有 `create_by` / `dept_id` 列且未声明语义，查询会报「列不存在」——这是刻意的，逼你把语义写清楚。

## 七、数据访问规则

优先级：**能用模型就用模型**。

| 场景 | 正确写法 |
|------|----------|
| 普通查询 | `User::where(...)->select()` |
| 列表（参与数据权限） | `User::newScopedQuery()->paginate(...)` |
| 回收站列表 | `Model::onlyTrashed()` |
| 恢复 / 彻底删除 / 复用回收站节点 | `Model::withTrashed()` |
| 唯一性 / 存在性校验、配置候选项 | `Model::withoutGlobalScope()` |
| 查询构造器直查（基础设施 / 元数据） | `Db::name()` + 必要时 `SoftDelete::apply()` |

`support/SoftDelete.php` **只服务查询构造器直查场景**（回收站模块、`AuthService`、`DataScope`、调度进程等），能用模型的地方不要用它。

> 逃生口（`withoutGlobalScope()` / `withTrashed()`）**必须能从代码上看出来，并注明理由**。显式写出来好过隐式生效。

---

## 八、异常与响应

- 业务错误：`throw new ApiException('无权操作该用户', 403);`
- 控制器返回：`$this->ok($data)` / `$this->fail($msg, $code)`。
- 不要自己 `return new Response(...)`，统一走 `Result`。
- 异常码约定见 [04-框架介绍](04-框架介绍.md#51-约定俗成的错误码)。

---

## 九、配置读取

- 系统配置（可后台改）→ `SysConfig::getString/getInt/getBool/getList('key', 默认值)`。
- 静态配置（改代码才变）→ `config('plugin.cccms.xxx.yyy')`。
- 环境相关（数据库、密钥、存储凭证）→ `getenv()` 覆盖默认值。
- **不要**把可变配置读进进程内静态属性（长驻进程会不生效）。

---

## 十、注释规范

- 类注释写「职责 + 关键设计原因 + 陷阱」。
- 反直觉的写法**必须**注明「为什么这样做」，否则后人会「顺手修正」。
- 用 `// TODO:` 标注待办时，同步登记到 [`更新日志.md`](更新日志.md) 的「未发布」区。
- 不要写「这里做了 X」这种重复代码的废话注释，写「为什么是 X 而不是 Y」。

## 十一、新增一个业务插件的完整步骤

以 `plugin/shop`（商品管理）为例。

### 11.1 后端

1. **建目录**：

   ```
   server/plugin/shop/
   ├── app/controller/  app/logic/  app/model/
   ├── config/  (app.php / route.php / middleware.php / exception.php)
   └── db/      (menu.php / schema.sql / seed.sql)
   ```

2. **配置插件**：`plugin/shop/config/app.php` 返回 `['enable' => true]`；`route.php` 显式声明路由（`Route::disableDefaultRoute()`）。
   中间件：如需登录鉴权，挂上 `CheckLogin` / `CheckAuth` 等；不需要则仅 `Cors`。

3. **声明菜单**：`plugin/shop/db/menu.php` 声明目录与菜单（不声明按钮）：

   ```php
   return [
       [
           'slug' => 'shop', 'title' => '商城管理', 'type' => 1,
           'icon' => 'icon-apps', 'path' => '/shop', 'component' => '', 'sort' => 9,
           'children' => [
               ['slug' => 'shop:goods', 'title' => '商品管理', 'type' => 2,
                'path' => '/shop/goods', 'component' => 'shop/goods/index', 'icon' => 'icon-apps', 'sort' => 1],
           ],
       ],
   ];
   ```

4. **建表脚本**：`plugin/shop/db/schema.sql`（用 `CREATE TABLE IF NOT EXISTS`，幂等）；
   数据权限接入参考第 5 步。

5. **写模型**：参与数据权限就声明 `$dataScope`，否则 `false`。有 `create_by` 的表默认即可。

6. **写 Logic + Controller**：Controller 声明 `#[Permission(slug: 'shop:goods:index', title: '商品列表')]`。

7. **执行纳管命令**：

   ```bash
   php webman cccms:menu-sync            # 同步菜单
   php webman cccms:perm-scan            # 生成按钮节点
   php webman cccms:db-upgrade           # 执行插件 schema
   php webman cccms:data-scope-check     # 检查数据权限接入
   ```

8. **（可选）登记受控表**：需要配自定义数据规则时，在数据权限页「受控表」添加，或在 `db/seed.sql` 里 `INSERT`。

9. **（可选）扩展回收站类型**：`plugin/shop/db/recycle.php` 声明类型。

### 11.2 前端

10. **页面**：`frontend/src/pages/shop/goods/index.vue`，`defineOptions({ name: 'shop:goods' })`（**必须等于菜单 slug**）。
11. **接口封装**：`frontend/src/api/shop/goods.ts`。
12. 菜单 `component` 填 `shop/goods/index`，与页面路径对应。

> `plugin/index` 是「无 `db/menu.php` 的公开插件」范例，可参考它的最小配置。

## 十二、新增一个业务接口

见 [05-鉴权与权限 §九](05-鉴权与权限.md#九新增一个需要权限的接口)。要点：

1. Controller 加方法 + 注解；
2. `config/route.php` 注册路由；
3. `php webman cccms:perm-scan`；
4. 角色里授权；
5. 前端加 `v-auth` 按钮与接口封装。

## 十三、提交前检查清单

| # | 检查 | 命令 / 方式 |
|---|------|-------------|
| 1 | PHP 语法 | `php -l` 全部改动文件 |
| 2 | 权限节点已声明且合法 | `php webman cccms:perm-scan --check`（只校验不写库） |
| 3 | 菜单声明已同步 | `php webman cccms:menu-sync` |
| 4 | 数据权限接入无错误 | `php webman cccms:data-scope-check` |
| 5 | 数据规则无冲突 | `php webman cccms:data-rule-check` |
| 6 | 新表 / 新列已纳入升级脚本 | `php webman cccms:db-upgrade` |
| 7 | 后端单元测试 | `composer test`（库不可用时相关用例自动跳过） |
| 8 | 前端类型检查与构建 | `cd frontend && npm run build`（含 `vue-tsc --noEmit`） |
| 9 | 前端格式与 lint | `cd frontend && npm run format:check && npm run lint` |
| 10 | 文档与更新日志已同步 | 改动机制 / 接口 / 命令 / 配置则更新 `docs/` 与 [更新日志](更新日志.md) |

> 2 / 4 / 5 / 7 / 8 / 9 都已接入 CI（见 [11-常用命令与运维](11-常用命令与运维.md#十二ci-与质量门禁)）。
