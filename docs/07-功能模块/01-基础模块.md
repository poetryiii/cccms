## 一、工作台（Dashboard）

| 项 | 内容 |
|----|------|
| 功能 | 欢迎卡 + 统计卡（用户 / 角色 / 部门 / 岗位 / 菜单 / 今日日志 / 在线用户 / 未读消息 / 字典 / 定时任务 / 数据规则 / 租户）+ 7 天日志趋势折线 + 附件类型分布饼图 + 「我的收藏」宫格（可拖拽排序） |
| 表 | 只读聚合，不新增表 |
| 接口 | `GET /dashboard/stats`（`#[NoAuth]`，登录即可） |
| 前端 | `pages/cccms/dashboard/index.vue`，组件名 `dashboard`，静态路由 `/dashboard` |
| 权限节点 | 无（登录即可）；**每张统计卡按各自模块权限节点条件下发** |

**权限只有两层**（以「能不能进对应列表页」为准）：

| 层 | 看到什么 |
|----|----------|
| 超级管理员 | 全部统计卡与全部数据（`UserContext::hasPermission()` 直通） |
| 其他账号 | 只有持有权限节点的模块才有对应卡片，其余键**不下发**；数字本身再按数据范围收窄 |

注意事项：

- **统计口径与列表页一致**：`user` / `dept` / `file` / `log` 的计数按当前用户数据范围聚合，避免「列表只能看到 3 条、工作台显示 1000 条」的绕行泄漏。
- **卡片按权限节点逐项下发**：13 个计数项各自登记了「能进列表页」所需的权限节点
  （如 `user → cccms:user:index`、`dept → cccms:dept:tree`、`log / today_log → cccms:log:index`），
  无权限时该键**不存在**，前端按「键是否存在」决定是否渲染卡片 ——
  避免「进不去列表页、却能从工作台读出该模块数据量」的越权信息泄露。`notice_unread` 是本人消息数，恒返回。
- **图表同样按权限**：拿不到日志列表页时 `log_trend.dates` 为空数组（不渲染趋势卡），
  拿不到附件列表页时 `file_types` 为空数组。
- **「我的收藏」宫格**取 `menuStore.favoriteMenus`，与顶栏快捷导航、标签栏收藏按钮**共用同一份收藏**（改一处三处同步）；
  顺序即收藏顺序，卡片上可直接**拖拽排序**（原生 HTML5 拖拽，未引入第三方库）。数据源是当前账号可见菜单，天然不含无权限入口；未收藏任何菜单时显示引导文案。
- 用户 / 角色 / 部门 / 岗位只统计 `status = 1`；菜单只统计 `type = 2`；字典 / 定时任务只统计 `status = 1`。
- 日志趋势逐天补 0；附件类型按扩展名分组取前 6；单个模块计数异常时按 0 兜底，不因某张表故障导致整个工作台报错。
- ECharts 按需引入（`echarts/core`），主题切换时重渲染。

## 二、认证（Auth）

| 项 | 内容 |
|----|------|
| 功能 | 健康检查、登录、图形验证码、当前用户信息、登出 |
| 表 | `sys_user`、`sys_role`、`sys_user_role`、`sys_role_node`、`sys_tenant`（校验租户可用性） |
| 前端 | `pages/cccms/login/index.vue` |

| 方法 | 接口 | 注解 | 说明 |
|------|------|------|------|
| `ping` | `GET /ping` | `#[NoLogin]` | 健康检查，返回 `pong` + 时间 |
| `login` | `POST /auth/login` | `#[NoLogin]` | 账号密码（+ 可选验证码）登录，返回 token + 用户信息 |
| `captcha` | `GET /auth/captcha` | `#[NoLogin]` | 图形验证码；未开启时返回 `null` |
| `me` | `GET /auth/me` | `#[NoAuth]` | 当前用户信息（含 `crypto_key`） |
| `logout` | `POST /auth/logout` | `#[NoAuth(title:'注销')]` | 注销：服务端把当前 `jti` 写入黑名单并移除在线会话 |
| `tenants` | `GET /auth/tenants` | `#[NoAuth]` | 可切换的租户下拉：超管返回全部租户，其他账号只返回当前租户 |
| `switchTenant` | `POST /auth/switchTenant` | `#[NoAuth(title:'切换租户')]` | 超管显式切换租户：重签带 `tid` 声明的令牌 + 迁移在线会话 `jti` |

登录校验顺序（`AuthLogic::login`）：

1. `LoginThrottle::assertNotLocked()`（锁定 → 429）。
2. `security.login_captcha` 开启才校验验证码。
3. `User::withoutAllScopes()` 查账号（**用户名全局唯一 + 回收站账号不可登录**）+ `password_verify`。
4. 状态 `status !== 1` → 403。
5. `AuthService::buildContext()` 失败 → 「账号角色异常」。
6. 维护模式下仅超管可登录。
7. 成功后清失败计数、更新 `login_time` / `login_ip`。

注意事项：

- 登录成功后返回的 `user.permissions` 是前端 `v-auth` 的数据来源。
- 登出**已做服务端失效**：把当前 `jti` 写入 Redis 黑名单（TTL = 剩余有效期）+ 移除在线会话，
  `CheckLogin` 每次校验；令牌损坏 / 已过期时按「登出成功」处理，保证接口幂等。
- 登录成功 / 失败都会写入操作日志（`sys_log`，`path='/auth/login'`），见 [十三、操作日志](02-运维与日志.md#十三操作日志log)。
- **租户可用性逐请求校验**：`AuthService::buildContext()` 每次都会检查 `tid` 对应租户是否存在 / 未删除 /
  已启用 / 未过期 —— 租户被停用或到期后，该租户下所有账号**下一次请求即 401**，与「禁用用户立即生效」同一口径。
  详见 [二十一、租户管理](02-运维与日志.md#二十一租户管理tenant)。

## 三、个人中心（Profile）

| 项 | 内容 |
|----|------|
| 功能 | 查看本人资料、修改本人基本资料、修改本人密码、查看与注销本人登录设备 |
| 表 | `sys_user`、`sys_role`、`sys_user_dept`、`sys_dept` |
| 接口 | `GET /profile`、`POST /profile/update`、`POST /profile/password`、`GET /profile/sessions`、`POST /profile/sessions/revoke`（全部 `#[NoAuth]`） |
| 前端 | `pages/cccms/profile/index.vue`，**静态路由** `/profile`（不进左侧菜单，入口在右上角用户下拉） |
| 权限节点 | 无 |

注意事项：

- 目标**始终是 `$user->id`**，不接受外部传入 id（防越权）。
- 可改字段白名单：`nickname` / `avatar` / `email` / `phone`（不含 username / status / 角色 / 部门 / 岗位）。
- 改密需校验原密码 + `PasswordPolicy` + 新旧不能相同。
- 走 `User::withoutGlobalScope()` 逃生口，否则「本部门档 + 未分配部门」的用户会被数据权限 fail-closed 挡住读自己资料。
- **登录设备**：`GET /profile/sessions` 通过 `OnlineSession::listOfUser()` 仅返回 `user_id = 当前用户`
  的会话（含 `current` 标记）；`POST /profile/sessions/revoke` 用 `OnlineSession::ownerOf()` 校验归属，
  失败统一返回 404「会话不存在或已失效」（**不区分不存在 / 不是我的**，避免探测他人会话）；
  禁止注销当前会话（422，改用「退出登录」）；注销时 `TokenBlacklist::revoke()` + `OnlineSession::remove()`
  **两处同时生效**。设备 / 系统 / 浏览器由 UA 派生，口径与 `GET /online` 一致。

## 四、用户管理（User）

| 项 | 内容 |
|----|------|
| 功能 | 用户增删改查、分配角色 / 部门（多选）/ 岗位（多选）、重置密码 |
| 表 | `sys_user`、`sys_user_role`、`sys_user_dept`、`sys_user_post` |
| 前端 | `pages/cccms/user/index.vue`，组件名 `cccms:user` |

| 接口 | 权限节点 | 说明 |
|------|----------|------|
| `GET /user` | `cccms:user:index` | 分页列表（安全字段，不含 password） |
| `GET /user/read` | `cccms:user:read` | 详情（含 `role_ids` / `dept_ids` / `post_ids`） |
| `POST /user/save` | `cccms:user:save` | 新增（密码必填 + 密码策略） |
| `POST /user/update` | `cccms:user:update` | 更新（密码留空则不改） |
| `POST /user/delete` | `cccms:user:delete` | 软删除（不能删自己、不能删超管） |
| `POST /user/resetPassword` | `cccms:user:reset_password` | 重置密码 |
| `POST /user/batchStatus` | `cccms:user:batch_status` | 批量启用 / 禁用（`{ids, status}`） |
| `POST /user/batchDelete` | `cccms:user:batch_delete` | 批量软删除 |
| `POST /user/batchAssign` | `cccms:user:batch_assign` | 批量分配角色 / 部门 / 岗位（整体替换语义） |

注意事项：

- 数据权限全由模型层承担（行级范围 + 出参字段规则 + 入参剔除）。
- 唯一性 / 存在性校验显式 `withoutGlobalScope()`（含 `withTrashed`，**回收站账号仍占用用户名**）。
- 删除为软删，关联表（user_role / user_dept / user_post）保留。
- **批量操作**统一语义：**只作用于可见行 + 跳过并回报 + 不整批失败**。先经
  `User::newScopedQuery()->whereIn('id', $ids)` 取可见交集，再剔除「超管账号」与「操作者自己」，
  返回值固定为 `{affected, skipped[]}`；`skipped` = 越权 / 受保护 / 不存在的 id。
  批量禁用后对方**下一次请求即 401**（鉴权每请求查库）。
  `batchAssign` 为**整体替换**：传了哪个键就重设哪个关联，三个键都没传抛 422。
- **不提供导入 / 导出**：用户模块的 CSV 导入导出已下线（含模板下载），需要时用「操作日志」页的导出。

## 五、角色管理（Role）

| 项 | 内容 |
|----|------|
| 功能 | 角色增删改查、角色树、节点授权（含继承展示）、数据范围设置 |
| 表 | `sys_role`、`sys_role_node`、`sys_user_role` |
| 前端 | `pages/cccms/role/index.vue`，组件名 `cccms:role`（树形页：`ArtSplitView` + `ArtTreePanel`） |

| 接口 | 权限节点 | 说明 |
|------|----------|------|
| `GET /role` | `cccms:role:index` | 列表（可按 `node_id` 取子树） |
| `GET /role/tree` | `cccms:role:tree` | 角色树 |
| `GET /role/read` | `cccms:role:read` | 详情 + 节点（`own` / `inherited` 分开返回） |
| `POST /role/save` | `cccms:role:save` | 新增 |
| `POST /role/update` | `cccms:role:update` | 更新 |
| `POST /role/delete` | `cccms:role:delete` | 软删 |
| `POST /role/copy` | `cccms:role:copy` | 复制角色（含档位与自身节点授权，不复制子角色） |

注意事项：

- 超管角色（`code = super_admin`）**禁止编辑 / 删除**，`code` 不可改。
- 有子角色的角色不可删除。
- 保存节点授权时剔除 `nodes` / `own` / `inherited` 键（避免 `fields_strict` 报错）。
- 授权界面上，从父角色继承来的节点**只读**。
- 删除角色时 `role_node` / `user_role` 保留（彻底删除时才清）。
- **复制角色**：只复制角色本体与**自身** `role_node` 授权（不含继承来的祖先节点，避免源角色调整后副本失效），
  不复制子角色。**必须显式复制 `data_scope`** —— 档位刻意不继承（见 [05-鉴权与权限](../05-鉴权与权限.md)），
  漏复制会让副本静默落到默认「仅本人」。`name` 缺省「源名 + 副本」，`code` 自动派生 `_copy` / `_copy2`…；
  父角色做存在性 + 深度 ≤5 校验（同时兜住历史脏数据中的环）；传 `status=0` 即「另存为模板」，
  **不传 `status` 时沿用源角色的状态**（不覆盖）。

## 六、部门管理（Dept）

| 项 | 内容 |
|----|------|
| 功能 | 无限级部门树的增删改查；用户可多部门 |
| 表 | `sys_dept`、`sys_user_dept`、`sys_dept_role` |
| 前端 | `pages/cccms/dept/index.vue`，组件名 `cccms:dept`（树形页） |

| 接口 | 权限节点 |
|------|----------|
| `GET /dept/tree` | `cccms:dept:tree` |
| `POST /dept/save` | `cccms:dept:save` |
| `POST /dept/update` | `cccms:dept:update` |
| `POST /dept/delete` | `cccms:dept:delete` |

注意事项：

- 部门模型**参与**数据权限：「本部门及以下」档下部门管理页只见自己子树。
- **作用域过滤后树的根节点处理**：可见节点的父节点可能不在集合内（例如只看自己所属的二级部门），这类节点会被**提升为顶层**，否则整棵树会因为找不到 `parent_id = 0` 的根而变空。
- 删除前检查子部门与成员（**看全量**，不受数据范围影响），软删。
- 「绑定部门」候选项用 `DeptLogic::treeAll()`（全量）：规则是配置动作，不能因为看不见某个部门就绑不了。

- **批量操作**语义同用户模块（只作用于可见行 + 跳过并回报）。

注意事项：

- 读取走 `SysConfig`：Redis（TTL 300s）→ MySQL；保存后 `flush()` 立即失效（**刻意不做进程内缓存**）。
- `type = password` 的项以 `enc:` + `Cipher` 密文存储，前端留空表示不修改。
- 保存 `system.maintenance` 为真时会 `SessionGuard::cut()`，作废非超管旧 token。
- 前端「只提交变更项」，并有未保存离开拦截。

- 配置项名 i18n：`ConfigLogic::localize()` 按 `config_item.{name}` 覆盖 `title`，并额外下发 `group_label`（分组名翻译）。`group` **保持原值**——它是前端 `?group=` 过滤与分组归并的 key，翻译它会破坏过滤。
- **全局水印**：`watermark.*` 分组（开关 / 内容 / 不透明度 / 倾斜角度 / 字号 / 颜色 / 水平与垂直间距，默认关闭）。内容支持变量
  `{username}`/`{用户名}`（用户名）、`{user_id}`/`{用户ID}`（用户 ID）、`{time}`/`{时间}`（当前时间，按分钟刷新）、

  `components/Watermark.vue` 在 `BasicLayout` 叠加渲染（canvas 平铺 + `background-repeat`、`pointer-events: none`，
  盖在含弹窗的整层之上）；变量值取自当前登录用户，后端只下发渲染参数。

  `is_public = 1` 直链可访问（默认），`0` 则直链 `403`，只能登录后经 `GET /file/download` 读取
  （带数据权限；前端私有附件先取 blob 再渲染）。后台配置「允许匿名访问附件」是总开关，

  预览与下载统一走 `GET /file/download`（前端取 blob），直链会 403。

### 12.1 分片上传（P2-9）

- **前端自动分流**：同一个「上传」按钮，`file.size > upload.max_size`（默认 10MB）时改走分片，
  否则单请求直传（`el-upload` 的 `http-request` 自定义上传器，统一走 axios 实例）。
- **三阶段**：`init`（校验类型 / 总大小 → 尝试**秒传** → 建会话）→ `chunk`（逐片落盘，幂等可重传，
  每片上限 8MB）→ `complete`（校验片齐 → 合并 → 校验声明大小 / 哈希 → 交回 `FileLogic::upload` 入库）。
- **秒传**：前端对 ≤ 64MB 的文件用 WebCrypto 算 SHA-1（与服务端 `sha1_file` 同口径），
  `init` 命中「内容 hash + size 相同且**在数据范围内可见**」的记录时直接复用，连字节都不传；
  非 HTTPS 环境算不出哈希则跳过秒传（不影响续传）。
- **断点续传**：`init` 返回 `received` 已收分片列表，前端只补缺的那几片。
- **完整性**：合并后总字节数必须等于声明大小；声明了哈希的还要 `sha1_file` 对得上，
  否则拒绝 —— 挡住「漏传一片生成损坏附件」与「伪造秒传」。
- **四种驱动行为一致**：分片只暂存本地 `runtime/chunks/{uploadId}/`，`complete` 时把合并文件当成
  普通上传交给驱动（本地是 `rename`、云驱动是整体上传）。云厂商原生分片接口本轮不做
  （四种驱动各一套、需真账号联调，见 [开发计划](../开发计划.md) 的取舍）。
- **大小上限**：分片走 `upload.chunk_max_size`（默认 2048MB），通过 `FileLogic::upload(..., $maxBytes)`
  **显式传参**而非可变状态（驱动实例被 `StorageManager` 静态缓存，可变状态会跨请求串味）。
- **清理**：会话放 Redis（TTL 24h），磁盘目录由内置任务 `ChunkCleanTask`（每小时）与
  `init` 的顺带清理（每小时节流一次）按 mtime 回收；`complete` 后无论成败都清分片目录。
- 升级：`cccms:db-upgrade` 补 `upload.chunk_max_size` 配置项；新装 seed 内置清理任务。
  存量库在「定时任务」页新增一条 `plugin\cccms\command\task\ChunkCleanTask`（目标列表自动扫描到）。

更多存储机制见 [11-常用命令与运维](../11-常用命令与运维/02-配置与存储.md#六存储与附件)。
