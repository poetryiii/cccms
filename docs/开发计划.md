## 二、待办详情

### 2.1 安全加固

#### R-01 反代场景下的真实 IP 溯源

- **现状**：`$request->getRealIp()`（Webman 内置）被用于登录限流（账号 + IP 双维度）、登录日志、在线用户与
  操作日志 —— `app/logic/AuthLogic.php:62`、`app/middleware/CheckLogin.php:69`、
  `app/middleware/OperationLog.php:78/136`、`app/logic/LogLogic.php:61`、`app/controller/AuthController.php:75`。
  项目按 Docker / Nginx 反代部署，但**未见可信代理配置**。
- **问题**：若未按可信代理解析 `X-Forwarded-For`，IP 维度的防撞库限流可被伪造 XFF 绕过；
  反之若全部请求都归到网关 IP，又会误伤同局域网用户（触发红线）。
- **建议**：
  1. 增加 `trusted_proxies` 配置（CIDR 白名单），**仅**对可信代理来源解析 XFF，否则回退直连 IP；
  2. 采用「**取最右非可信 IP**」标准算法，杜绝 XFF 拼接注入；
  3. 在 [02-安装部署](02-安装部署.md) 补充反代部署的 IP 溯源说明与 Nginx 配置样例。
- **验收**：反代下伪造 XFF 无法绕过限流；登录日志中的 IP 正确。
- **工作量**：0.5~1 pd。

#### R-02 写入口字段白名单（防 Mass Assignment）

- **现状**：写接口把 `$request->post()` **整数组**直接传入写库（`app/controller/UserController.php:33/40`
  → `app/logic/UserLogic.php:94/118`）；字段收敛依赖 `ScopedQuery` 对 `hidden` / `mask` / `encrypt` / `readonly`
  的剔除 + 租户回填。
- **问题**：该设计自洽，但「普通业务字段的可写集合」是**隐式**的，靠各模型声明约束，新增字段时容易漏。
- **建议**：
  1. 在 `support/FilterInput.php` 增加 `only(array $raw, array $allow)` 工具方法；
  2. 每个写方法入口显式声明白名单：`$data = FilterInput::only($data, ['username','nickname','email', ...])`；
  3. 参照 `data-scope-check` 机制，把「写方法必须声明白名单」纳入**静态校验**。
- **验收**：未声明字段无法写入；扫描命令能拦截未白名单的写方法。
- **工作量**：1~2 pd。

#### R-03 依赖供应链安全审计（CI）

- **现状**：`.github/workflows/php.yml`、`frontend.yml` 无 `composer audit` / `npm audit`。
- **问题**：第三方依赖漏洞没有自动化检测入口。
- **建议**：两条 CI 流水线分别追加 `composer audit --no-dev` 与 `npm audit --audit-level=high`，失败即阻断合并。
- **验收**：CI 中高危依赖漏洞会阻断合并。
- **工作量**：0.3 pd。

### 2.2 测试与工程化

#### P1-7 引入前端单元测试

- **现状**：`frontend/package.json` 无 `test` 脚本、无测试框架；CI 仅 `format:check → lint → i18n:check → build`。
  纯前端逻辑（`useTable` 筛选方案序列化、`utils/cron.ts` 解析、`utils/richText.ts` 净化、`utils/password.ts` 校验、
  `stores/user.ts` 权限判定、`request.ts` 拦截分支）**完全没有回归保护**。
- **建议**：引入 Vitest（与 Vite 同源）+ `@vue/test-utils`；优先覆盖上述纯函数与 composable；
  新增 `npm run test` / `test:coverage`；CI 增加 Test 步骤并置于 `build` **之前**；
  顺带覆盖登录失败双维度锁定（账号维度 / IP 维度）的前端用例（登录页锁定提示），与 R-05 的后端集成用例互补。
- **验收**：`npm run test` 本地通过；CI 中测试失败阻断流水线；核心工具函数覆盖率 ≥ 70%；
  [09-前端开发规范](09-前端开发规范.md) 补「前端测试怎么写」小节。
- **工作量**：3 pd。

#### R-05 后端集成测试补强

- **现状**：`server/tests` 有 15 个用例，但**需要库的集成测试在本地无库时自动跳过**（`tests/run.php`）。
- **问题**：`LoginThrottle` 双维度锁定、`DataScope` 集成、租户边界等「依赖真实 Redis / MySQL」的行为覆盖不足。
- **建议**：CI 里显式起 MySQL / Redis 服务跑完整集成测试（现状仅「服务就绪时才执行」）；
  把登录双维度、租户跨库校验加为**常驻**用例。
- **验收**：CI 集成测试必跑不跳；核心安全链路有回归用例。
- **工作量**：1~2 pd。

### 2.3 性能与可观测

#### P2-11 性能基线与压测沉淀

- **现状**：性能优化点（数据权限请求级缓存、在线会话分段扫描）均来自设计推断，**无实测基线**，
  后续改动无法判断是否回归；N+1 除导出外未系统排查。
- **建议**：用 k6 / wrk 对 6 个高频接口（用户列表、角色树、菜单树、日志列表、在线用户、我的消息）
  建立基线脚本并纳入仓库；记录 P95 / QPS / DB 查询数；结论沉淀进文档作为回归对照。
- **验收**：6 个接口有可复现基线；脚本一条命令可跑；基线写入文档；发现的 N+1 独立立项。
- **工作量**：3 pd。

#### P2-12 指标暴露（`/metrics`）

- **现状**：健康检查 `GET /ping` 仅返回 `pong` + 时间；已有 `traceId` 与慢接口告警但只写文件/库，
  **无可被采集的指标端点**，无法接入 Prometheus 做容量与错误率告警。
- **建议**：新增 `GET /metrics`（`#[NoLogin]` + IP 白名单），暴露请求数、错误数、P95 耗时、
  Redis / DB 连通性、在线会话数、定时任务最近执行状态；输出 Prometheus 文本格式。
- **验收**：可被 Prometheus 抓取；非白名单 IP 返回 404/403；指标值与实际一致。
- **工作量**：3 pd。

#### P2-14 审计日志防篡改

- **现状**：`sys_log` 由应用直接 `INSERT`，记录可被 DBA 或拥有库权限的人直接 `UPDATE` / `DELETE`，
  不满足合规审计对**完整性**的要求；已有日志归档解决的是「容量」而非「可信」。
- **建议**：为 `sys_log` 增加 `prev_hash` / `row_hash` 链式字段；提供 `cccms:log-verify` 校验并定位断点；
  归档文件记录该批次尾哈希便于离线核验；保留现有清理策略不变。
- **验收**：篡改任一行后校验命令能定位到该行；正常写入性能无显著劣化（**待确认**需实测）；
  归档文件可离线校验。
- **工作量**：4 pd。

### 2.4 功能补齐

#### P2-7 导出异步化 / 导出任务中心

- **现状**：`GET /user/export`、`GET /data-rule/export`、`GET /log/export` 均**同步返回文件流**
  （`support/Csv.php` 用 `php://temp` 流式写，内存安全），但响应时间随数据量线性增长；
  前端 axios 超时 15s（`frontend/src/api/request.ts:22`），大表导出可能直接超时。导入侧已有 5000 行 / 5MB 上限，
  **导出侧无上限**。**待确认**：生产实际数据量下是否已出现超时。
- **建议**：超过阈值（如 1 万行）切换为异步「写任务表 + 消费 + 归档文件」；前端增加导出任务抽屉；
  小数据量仍走同步以保持现有体验；导出文件设有效期 + 定时清理；**导出侧补行数上限兜底**（对齐导入侧做法）。
- **验收**：10 万行导出不阻塞在线请求且能完成；前端可查看状态并下载；小数据量体验不变；文件按配置过期清理。
- **工作量**：6 pd。

#### P2-9 附件分片上传 / 秒传

- **现状**：单请求上传，受 `upload.max_size`（默认 10MB）限制；已有按 `hash` 的内容去重，
  但**发生在完整上传之后**，不节省传输；弱网失败需整包重传。
- **建议**：新增 `POST /file/upload/init`（返回 uploadId + 已存在分片）、`/file/upload/chunk`、
  `/file/upload/complete`；init 阶段用文件 hash 命中已有记录直接秒传；分片临时文件落 `runtime/` 并超时清理；
  云存储驱动优先用其原生分片接口。
- **验收**：100MB 文件可上传成功；弱网中断可续传；秒传命中不重复占用存储；未完成分片定时清理；
  四种存储驱动行为一致（**待确认**云驱动实现成本）。
- **工作量**：6 pd。

#### P2-13 登录安全分析视图

- **现状**：登录成功/失败均已落 `sys_log`（`path = '/auth/login'`），可筛选可导出，但**只有明细没有聚合**，
  撞库 / 异地登录 / 异常时段登录需人工翻列表。
- **建议**：新增 `GET /log/login/analysis`：按天/按小时的失败趋势、失败 TOP 用户名、失败 TOP IP、
  成功但 IP 变更的记录；前端日志页增加「登录分析」标签页（复用 ECharts）。
- **验收**：能列出失败 TOP10 用户名 / IP；趋势图正确；数据受数据权限约束
  （**待确认**：`sys_log` 当前设计为不参与数据权限）。
- **工作量**：3.5 pd。

#### P2-3（遗留）生产环境接入真实网关

- **现状**：密码找回链路已通，但邮件 / 短信通道以**可插拔适配器**实现，未配置真实网关时降级为日志输出
  （开发环境可完整走通找回流程）。
- **建议**：生产部署前在 `sys_config` 配置 SMTP / 短信服务商参数并验证送达率；
  确认找回接口已挂验证码 + IP 限流。
- **验收**：真实环境能收到找回邮件 / 短信。
- **工作量**：按所选网关 1~3 pd（配置动作，非代码改造）。

## 三、维护约定

1. **先登记再动手**：新增功能前先在 §一 登记条目（含工作量估算），方案细节写进 §二；
   **完成后从本文件移除**，并把实现与验收结论写入 [更新日志](更新日志.md) 对应版本。
2. **一个功能只有一个编号**：登记前先检索全文，与已有编号重复的只在原编号下补细节，不另开编号。
3. **判为「不做」的条目**：不留在本文件，改为写进更新日志的 [「明确不做」](更新日志.md#明确不做) 并写明原因。
4. **依据必须可核验**：条目必须写明 `文件:行号` 依据；无法确认的标「待确认」，不得以推测代替事实。
5. **文档随代码一起改**：改动机制、接口、命令、配置、表结构时，必须同步更新对应文档（约定见 `docs/README.md`）。
6. **验收口径**：功能「已完成」= 接口可用 + 页面可用 + 权限节点已生成 + 文档已更新 +
   通过 [08-后端开发规范](08-后端开发规范.md#十三提交前检查清单) +
   通过 `cccms:perm-scan --check` / `cccms:data-scope-check` / `cccms:data-rule-check`。
7. **本计划面向功能与质量**；具体实现约定见 [08-后端开发规范](08-后端开发规范.md) 与
   [09-前端开发规范](09-前端开发规范.md)。
