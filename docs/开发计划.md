## 二、待办条目详情

> 已完成条目不再重复「现状 / 方案 / 验收」，其结论已写入对应更新日志；本节只保留**未完成条目**与
> **已完成但留有遗留项**的条目。

### 2.1 未完成条目

#### P1-7 引入前端单元测试

- **现状**：`frontend/package.json` 无 `test` 脚本、无测试框架；CI 仅 `format:check → lint → i18n:check → build`。
  纯前端逻辑（`useTable` 筛选方案序列化、`utils/cron.ts` 解析、`utils/richText.ts` 净化、`utils/password.ts` 校验、
  `stores/user.ts` 权限判定、`request.ts` 拦截分支）**完全没有回归保护**。
- **建议**：引入 Vitest（与 Vite 同源）+ `@vue/test-utils`；优先覆盖上述纯函数与 composable；
  新增 `npm run test` / `test:coverage`；CI 增加 Test 步骤并置于 `build` 之前。
- **验收**：`npm run test` 本地通过；CI 中测试失败阻断流水线；核心工具函数覆盖率 ≥ 70%；
  `docs/09-前端开发规范.md` 补「前端测试怎么写」小节。
- **工作量**：3 pd。

#### P2-7 导出异步化 / 导出任务中心

- **现状**：`GET /user/export`、`GET /data-rule/export`、`GET /log/export` 均**同步返回文件流**
  （`support/Csv.php` 用 `php://temp` 流式写，内存安全），但响应时间随数据量线性增长；
  前端 axios 超时 15s（`frontend/src/api/request.ts`），大表导出可能直接超时。导入侧已有 5000 行 / 5MB 上限，
  **导出侧无上限**。**待确认**：生产实际数据量下是否已出现超时。
- **建议**：超过阈值（如 1 万行）切换为异步「写任务表 + 消费 + 归档文件」；前端增加导出任务抽屉；
  小数据量仍走同步以保持现有体验；导出文件设有效期。
- **验收**：10 万行导出不阻塞在线请求且能完成；前端可查看状态并下载；小数据量体验不变；文件按配置过期清理。
- **工作量**：6 pd。

#### P2-9 附件分片上传 / 秒传

- **现状**：单请求上传，受 `upload.max_size`（默认 10MB）限制；已有按 `hash` 的内容去重，
  但**发生在完整上传之后**，不节省传输；弱网失败需整包重传。
- **建议**：新增 `POST /file/upload/init`（返回 uploadId + 已存在分片）、`/file/upload/chunk`、
  `/file/upload/complete`；init 阶段用文件 hash 命中已有记录直接秒传；分片临时文件落 `runtime/` 并超时清理；
  云存储驱动优先用其原生分片接口。
- **验收**：100MB 文件可上传成功；弱网中断可续传；秒传命中不重复占用存储；未完成分片定时清理；
  四种存储驱动行为一致（**待确认**云驱动实现成本）。
- **工作量**：6 pd。

#### P2-10 导入导出增强

- **现状**：仅用户与数据权限规则支持导入；导出列由后端硬编码，无法按需裁剪。
  通用能力 `support/Csv.php`（BOM、公式注入防护、行数/大小上限）已具备，扩展成本低。
- **建议**：字典类型/数据、操作日志增加导入（日志导入建议仅支持「历史数据迁移」场景）；
  导出接口增加 `columns` 参数并按白名单校验；前端导出对话框支持列勾选并记住偏好；
  所有导出仍强制走数据权限作用域。
- **验收**：字典可导入并回报行级失败；导出可选列且非法列名被拒；导出内容仍受数据权限约束。
- **工作量**：5 pd。

#### P2-11 性能基线与压测沉淀

- **现状**：性能优化点（数据权限请求级缓存、在线会话分段扫描）均来自设计推断，**无实测基线**，
  后续改动无法判断是否回归；N+1 除导出外未系统排查。
- **建议**：用 k6 / wrk 对 6 个高频接口（用户列表、角色树、菜单树、日志列表、在线用户、我的消息）
  建立基线脚本并纳入仓库；记录 P95 / QPS / DB 查询数；结论沉淀进文档作为回归对照。
- **验收**：6 个接口有可复现基线；脚本一条命令可跑；基线写入文档；发现的 N+1 独立立项。
- **工作量**：3 pd。

#### P2-12 指标暴露（`/metrics`）

- **现状**：健康检查 `GET /ping` 仅返回 `pong` + 时间；已有 `traceId` 与慢接口告警但只写文件/库，
  **无可被采集的指标端点**，无法接入 Prometheus 做容量与错误率告警。
- **建议**：新增 `GET /metrics`（`#[NoLogin]` + IP 白名单），暴露请求数、错误数、P95 耗时、
  Redis / DB 连通性、在线会话数、定时任务最近执行状态；输出 Prometheus 文本格式。
- **验收**：可被 Prometheus 抓取；非白名单 IP 返回 404/403；指标值与实际一致。
- **工作量**：3 pd。

#### P2-13 登录安全分析视图

- **现状**：登录成功/失败均已落 `sys_log`（`path = '/auth/login'`），可筛选可导出，但**只有明细没有聚合**，
  撞库 / 异地登录 / 异常时段登录需人工翻列表。
- **建议**：新增 `GET /log/login/analysis`：按天/按小时的失败趋势、失败 TOP 用户名、失败 TOP IP、
  成功但 IP 变更的记录；前端日志页增加「登录分析」标签页（复用 ECharts）。
- **验收**：能列出失败 TOP10 用户名 / IP；趋势图正确；数据受数据权限约束（**待确认**：`sys_log` 当前设计为不参与数据权限）。
- **工作量**：3.5 pd。

#### P2-14 审计日志防篡改

- **现状**：`sys_log` 由应用直接 `INSERT`，记录可被 DBA 或拥有库权限的人直接 `UPDATE` / `DELETE`，
  不满足合规审计对**完整性**的要求；已有日志归档解决的是「容量」而非「可信」。
- **建议**：为 `sys_log` 增加 `prev_hash` / `row_hash` 链式字段；提供 `cccms:log-verify` 校验并定位断点；
  归档文件记录该批次尾哈希便于离线核验；保留现有清理策略不变。
- **验收**：篡改任一行后校验命令能定位到该行；正常写入性能无显著劣化（**待确认**需实测）；
  归档文件可离线校验。
- **工作量**：4 pd。

#### P2-18 插件脚手架 `cccms:plugin-create`

- **现状**：新建业务插件需手工复制 `server/plugin/index` 骨架并自行登记 `db/menu.php`，易漏项；

#### P2-17 多租户：设计口径与隔离边界

- **四个已确认口径**：
  1. **隔离方式**：单库共享表 + `tenant_id`；`tenant_id = 0` 为平台/默认租户，**单租户部署行为完全不变**；
  2. **超管跨租户**：**显式切换租户**——JWT 带 `tid` 声明并重新签发令牌（不可伪造、可审计），不做隐式「超管看全部」；
  3. **用户名唯一性**：`username` **保持全局唯一**（不动 `uk_username`），登录无需租户解析，避免历史数据迁移；
  4. **隔离范围**：全部业务表（user / dept / role / post / data_rule / data_scope_table / notice / file /
     category / dict_type / dict_data / crontab）；菜单、配置、日志、定时任务日志、关联表保持**平台级**。
- **关键实现约定**：租户过滤必须是**独立的最外层全局作用域**（`$globalScope = ['tenant', 'dataScope']`，tenant 在前）。
  若把租户条件塞进 `DataScope::row()` 内，会因「超管直接 return」「档位 1（全部数据）直接 return」而**跨租户泄露**。
- **与数据权限的关系**：租户是**硬边界**（不可通过档位放宽），数据权限是租户**内部**的软范围；
  两者串联而非替代。`tenant_id = 0` 时租户作用域不产生任何条件。
- **验收**：① 跨租户数据不可见（含统计 / 导出 / 回收站）；② 现有单租户部署行为不变（回归通过）；
  ③ 超管切换租户后 `tid` 与在线会话 `jti` 一致迁移；④ 文档同步。**四项均已通过**。
- **实现落点**（后端）：`support/TenantContext.php`（`PLATFORM_ID` / `TABLES` / `participates()` /
  `table()` / `applyToQuery()` / `stamp()`）、`app/model/Tenant.php`、`app/model/BaseModel.php`
  （`$globalScope = ['tenant','dataScope']`、`withoutGlobalScope()` 保留租户、新增 `withoutAllScopes()`）、
  `app/model/ScopedQuery.php`（写入 `stamp()`）、12 个业务模型的 `$tenantScope = true`、
  `support/UserContext.php` / `support/AuthService.php`（生效租户与归属租户）、
  `support/TokenService.php` + `app/middleware/CheckLogin.php`（`tid` 声明与校验）、
  `app/logic/TenantLogic.php` + `app/controller/TenantController.php` +
  `app/controller/AuthController.php`（`/auth/tenants`、`/auth/switchTenant`）、
  `config/route.php`、`db/menu.php` 的 `cccms:tenant`、`command/DbUpgradeCommand.php`（幂等升级）。
- **实现落点**（前端）：`api/tenant.ts`、`pages/cccms/tenant/index.vue`、
  `layouts/components/LayoutHeader.vue`（租户切换器）、`api/auth.ts` + `stores/user.ts`
  （`tenantId` / `homeTenantId` / `tenantSwitched` 与 `switchTenant()`）、

- **验证**：后端 `php tests/run.php` 69 通过 0 失败、`cccms:perm-scan --check`（132 个方法）、
  `cccms:data-scope-check` 均通过，`cccms:db-upgrade` 重复执行 0 变更；前端
  `vue-tsc` / `lint` / `format:check` / `i18n:check`（1036 key × 2）/ `build` 全部通过。
- **后续注意**：新增业务表若需隔离，先加 `sys_tenant` 侧登记与 `TenantContext::TABLES` 条目，
  并在模型上显式声明 `$tenantScope = true`；Logic 层禁止用 `Db::name('受控表')`

#### P2-19 公共富文本编辑器的使用边界

- **设计约束（用户明确要求）**：**只有需要长文的地方才能用富文本编辑器**。

- **安全约定**：富文本存库为 HTML，因此有两道净化——

- **建议**：后续新增长文场景（如帮助中心、协议正文）再复用该组件，不要为短文本引入富文本依赖。
