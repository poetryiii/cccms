## 二、待办详情

### 2.1 安全加固

#### R-12 开发依赖告警处置（Vite / esbuild）

- **现状**：R-03 已把 `composer audit --no-dev` 与 `npm audit --omit=dev --audit-level=high`
  接进 CI，**生产依赖已清零**；但完整 `npm audit`（含开发依赖）仍报 2 条中危：
  `esbuild <= 0.24.2`（开发服务器允许任意站点发请求并读取响应，GHSA-67mh-4wv8-2f99）
  与经它传递的 `vite <= 6.4.2`（`frontend/package-lock.json`）。
- **问题**：这两条不进生产包，但会把「本地 `npm audit`」与「CI 门禁」的结论拉成不一致，
  容易被误读成「门禁放水」。
- **建议**：`npm audit fix --force` 会把 Vite 从 5 直接推到 8（跨 3 个大版本），
  并牵连 `@vitejs/plugin-vue` / `@tailwindcss/vite` 的兼容矩阵，
  风险远大于「本地开发服务器」这一暴露面；因此**暂不升级**，改为登记跟踪：
  待上游 `@tailwindcss/vite` 明确支持 Vite 8 后，一次性做工具链升级，
  并同步验证 `build` / `lint` / `format:check` / `i18n:check`。
- **验收**：生产依赖审计保持 0 告警（已达成）；开发依赖告警在工具链升级后清零，
  或明确判定为「不修」并转入 [更新日志「明确不做」](更新日志.md#明确不做)。
- **工作量**：待评估（取决于 Vite 8 的生态兼容情况）。

### 2.2 性能与可观测

#### P2-11 性能基线与压测沉淀

- **现状**：性能优化点（数据权限请求级缓存、在线会话分段扫描）均来自设计推断，**无实测基线**，
  后续改动无法判断是否回归；N+1 除导出外未系统排查。
- **建议**：用 k6 / wrk 对 6 个高频接口（用户列表、角色树、菜单树、日志列表、在线用户、我的消息）
  建立基线脚本并纳入仓库；记录 P95 / QPS / DB 查询数；结论沉淀进文档作为回归对照。
- **验收**：6 个接口有可复现基线；脚本一条命令可跑；基线写入文档；发现的 N+1 独立立项。
- **工作量**：3 pd。
- **代码侧进度（2026-09-27）**：压测脚本已就绪 —— [`server/loadtest/baseline.js`](../../server/loadtest/baseline.js)
  （k6，一条命令跑 6 个接口，支持 TOKEN / 账号密码两种鉴权）与运行说明已写入
  [11-常用命令与运维 §9.1](11-常用命令与运维.md#91-性能基线p2-11)。
  剩余为「**实测基线**」：本机无 k6/wrk 等压测工具、开发库数据量不具生产代表性，
  真实 P95 / QPS / DB 查询数需在**目标数据量 + 目标硬件**的压测环境跑一次后填入 §9.1 的基线表。

### 2.3 功能补齐

#### P2-3（遗留）生产环境接入真实网关

- **现状**：密码找回链路已通，但邮件 / 短信通道以**可插拔适配器**实现，未配置真实网关时降级为日志输出
  （开发环境可完整走通找回流程）。
- **建议**：生产部署前在 `sys_config` 配置 SMTP / 短信服务商参数并验证送达率；
  确认找回接口已挂验证码 + IP 限流。
- **验收**：真实环境能收到找回邮件 / 短信。
- **工作量**：按所选网关 1~3 pd（配置动作，非代码改造）。
- **代码侧进度**：网关接入的**配置步骤与验证项已文档化**在
  [02-安装部署 §5.6](02-安装部署.md#56-接入找回密码真实网关p2-3上线前必配)，
  剩余为「拿到真实服务商凭证后在 `sys_config` 填参数并实测送达」的部署动作，无法在代码仓库内完成。

## 三、维护约定

1. **先登记再动手**：新增功能前先在 §一 登记条目（含工作量估算），方案细节写进 §二；
   **完成后从本文件移除**，并把实现与验收结论写入 [更新日志](更新日志.md) 对应版本。
2. **一个功能只有一个编号**：登记前先检索全文，与已有编号重复的只在原编号下补细节，不另开编号。
3. **判为「不做」的条目**：不留在本文件，改为写进更新日志的 [「明确不做」](更新日志.md#明确不做) 并写明原因。
4. **依据必须可核验**：条目必须写明 `文件:行号` 依据；无法确认的标「待确认」，不得以推测代替事实。
5. **文档随代码一起改**：改动机制、接口、命令、配置、表结构时，必须同步更新对应文档（约定见 `docs/README.md`）。
6. **验收口径**：功能「已完成」= 接口可用 + 页面可用 + 权限节点已生成 + 文档已更新 +
   通过 [08-后端开发规范](08-后端开发规范.md#十四提交前检查清单) +
   通过 `cccms:perm-scan --check` / `cccms:data-scope-check` / `cccms:data-rule-check` /
   `cccms:write-guard-check` + `composer analyse` + `composer cs:check`。
7. **本计划面向功能与质量**；具体实现约定见 [08-后端开发规范](08-后端开发规范.md) 与
   [09-前端开发规范](09-前端开发规范.md)。
