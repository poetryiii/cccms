### 3.3 待决策

> 三项均已定案，无遗留待决策项。

| 事项 | 状态 | 结论 |
|------|------|------|
| 角色档位是否继承父角色 | `[~]` | **定案：不继承**。档位只取「直连角色」中最宽松的一档（`min`），祖先角色的档位不参与；有效角色（直连 + 祖先）仅用于「规则绑定角色」与 `{role.ids}`。理由：避免父角色「全部数据」把子角色**隐式扩权**（继承会把授权变成提权通道），且与档位默认值 4（仅本人）的 fail-closed 兜底方向一致 |
| 通知公告是否需要已读回执统计报表 | `[x]` | **已实现**：`NoticeLogic::readReport()` + 管理端「回执」抽屉（应读人数 / 已读人数 / 已读明细，口径与推送侧一致） |
| 是否内置 UI 自动化测试基线 | `[~]` | **定案：不做**。理由：E2E 用例随 UI 变动长期维护成本高，且现有「集成测试 + 前端 build/lint」已覆盖鉴权与数据权限主链路；如后续引入，再单独立项 |

## 四、后续规划

### 近期（2.1.0）· 已交付

1. **P0 待办清零**：在线会话服务端分页 + 分段扫描、强下线黑名单 TTL 精确到原令牌 `exp`。
2. **集成测试**：鉴权矩阵、数据权限三档、回收站 `withTrashed` 陷阱已入 CI。
3. **通知公告定向投放 + 已读回执报表**：`sys_notice_target` + 发布范围选择 + 回执抽屉。
4. **其余增强**：导入用户支持角色 / 部门 / 岗位、定时任务独立重试表、慢接口告警、
   数据权限规则导入导出、前端路由级权限守卫与筛选方案保存、附件 PDF 预览、
   ESLint 10、前后端 i18n、日志归档到对象存储（`cccms:log-archive`）。

### 中期（2.2.0）

1. **可观测性**：按 `traceId` 的链路聚合视图（把一次请求的多条日志串成时间线）。
2. **导入导出增强**：字典 / 日志的导入、导出模板自定义列。
3. **性能基线**：对高频列表接口做压测与 N+1 排查，沉淀可回归的基准数据。
4. **上游代码同步文档化**：`cccms:update` 的用法 / 退出码 / 升级流程补进文档（见更新日志）。

### 长期（3.x）

1. **多租户**：在数据权限基础上增加 `tenant_id` 维度（需评估对现有模型层的影响）。
2. **插件市场**：把「新建业务插件」的脚手架能力产品化（`cccms:plugin-create`）。
3. **前端 E2E**：如团队后续接受用例维护成本，再引入 Playwright 覆盖登录 → 授权 → 增删改查主链路。

## 五、维护约定

- 新增功能前，先在本文档「未开发」中确认是否已列入计划；完成后移动到「已完成」并标注版本。
- 状态变更（`[ ]` → `[x]`）时同步更新 [更新日志](更新日志.md) 的对应版本条目。
- 「明确不做」的条目必须写清原因，避免被反复讨论。
- 本计划面向**功能**；具体实现约定见 [08-后端开发规范](08-后端开发规范.md) 与 [09-前端开发规范](09-前端开发规范.md)。
