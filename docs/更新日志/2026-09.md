## 2026-09-18

> 同日两批合并记录：「文档体系 + 能力补齐 + 工程化」与「交付质量补齐」。

### 后端

- **【新增】国际化（i18n）**
  - 问题内容：后端无语言包，locale 无从解析。
  - 修复内容：`support/I18n.php` + `lang/{zh-CN,en-US}/*.php`，locale 解析优先级 `?lang=` → `Accept-Language` → 配置默认。

- **【新增】通知公告**
  - 问题内容：无站内通知能力，只能靠群消息。
  - 修复内容：`sys_notice` / `sys_notice_read` + 管理页面 + 顶栏「我的消息」抽屉与未读角标。

- **【新增】通知公告定向投放**
  - 问题内容：公告只能全员可见，部门 / 角色级通知只能靠人盯。
  - 修复内容：新增 `sys_notice_target` 关系表，发布范围支持全部 / 按部门 / 按角色 / 指定用户，阅读侧按同一口径过滤。

- **【新增】通知公告已读回执**
  - 问题内容：管理员不知道谁读了公告。
  - 修复内容：`NoticeLogic::readReport()` + 管理端「回执」抽屉（应读 / 已读 / 明细）。

- **【新增】日志归档到对象存储**
  - 问题内容：历史日志只能留在库里，按天清理会直接丢数据。
  - 修复内容：`cccms:log-archive` + `LogArchiver`（先上传成功再按 id 删除）+ `LogRedactor`；内置任务默认停用。

- **【新增】存储驱动 `put()` / `objectPath()`**
  - 问题内容：驱动只能按生成的文件名写入，无法指定目录，也无法拿到相对路径。
  - 修复内容：支持指定路径写入并防目录穿越，四个驱动统一实现。

- **【新增】在线用户 / 强制下线**
  - 问题内容：无法感知当前在线会话，账号被盗后只能改密码。
  - 修复内容：`support/OnlineSession.php`（`cccms:online:s:{jti}` + `cccms:online:index`）、Logic / Controller 与页面；支持按会话或按用户强制下线并作废已发令牌。

- **【新增】登录日志**

- **【新增】通用 CSV 导入 / 导出**

## 2026-09-17

> 数据权限下沉到模型层：本项目规模最大的一次重构——数据权限由「Logic 显式调用」改为「模型层自动生效」。
> 升级注意：`sys_data_rule` 结构有变，需重建或手工迁移。

### 后端

- **【新增】`BaseModel` 全局查询作用域**
  - 问题内容：数据权限靠 Logic 显式调用，漏调即越权。
  - 修复内容：`$globalScope` + `scopeDataScope()` + `$dataScope` 声明位 + `newScopedQuery()`。

- **【新增】请求级 scope plan**
  - 问题内容：每次模型查询都重新解析角色 / 岗位 / 部门 / 规则，同请求内重复开销大。
  - 修复内容：`DataScope` 用 `WeakMap`（键为 `UserContext` 实例）缓存解析结果，一次请求只解析一次（实测同请求 10 次模型查询，数据权限 SQL 0 条）。

- **【新增】写入侧字段级防护**
  - 问题内容：`hidden` / `readonly` / `mask` / `encrypt` 字段仍可被写入。
  - 修复内容：`app/model/ScopedQuery.php` 在 `insert` / `update` / `save` / `insertAll` 前剔除这些字段。

- **【新增】检查命令 `cccms:data-scope-check`**
  - 问题内容：控制器直连库、受控表无模型等违规无法自动发现。
  - 修复内容：R1 控制器不得直连库；R2 受控表必须有模型且不得声明 `$dataScope = false`；自动发现业务插件，首轮抓出 10 处漏网。

- **【新增】规则体检 `cccms:data-rule-check`**
  - 问题内容：互斥条件、同字段多动作、恒不生效规则只能靠人看出。
  - 修复内容：只报可证明为空的组合（条件互斥 / 同字段多动作 / 恒不生效 / 表未受控）。

- **【新增】规则绑定关系「或 / 且」**
  - 问题内容：多条规则只能全部命中，无法或组合。
  - 修复内容：新增 `bind_mode`。

- **【新增】受控表管理**
  - 问题内容：哪些表参与数据权限只写在代码里，运维改不了。
  - 修复内容：`sys_data_scope_table` + 管理界面。

- **【变更】自定义档（`data_scope = 5`）fail-closed**
  - 问题内容：规则缺失或未命中时默认放行，等于没权限约束。
  - 修复内容：没有规则或一条都没命中 = 看不到任何数据，无条件成立。

- **【变更】软删除下沉到模型层**
  - 问题内容：软删除只在部分 Logic 生效，模型查询与 `Db::name` 行为不一致。
  - 修复内容：`BaseModel` 使用 `SoftDelete` trait；`support/SoftDelete.php` 只服务查询构造器直查场景。

- **【变更】Logic 层迁移**
  - 问题内容：用户 / 角色 / 部门 / 岗位 / 附件 / 定时任务 / 操作日志 / 数据权限规则 8 个 Logic 仍用 `Db::name()` 直查，绕过权限。
  - 修复内容：8 个 Logic 的 `Db::name()` 清零，全部改走模型。

- **【修复】回收站无法恢复**
  - 问题内容：恢复时把待恢复行自己算作占用，唯一性冲突，user / role / post / dict_type / menu 全部恢复失败。
  - 修复内容：占用判定排除待恢复行本身。

- **【修复】工作台口径泄漏**
  - 问题内容：`DashboardLogic` 显示全量总数，无权限用户也能看到整体规模。
  - 修复内容：改为随数据范围聚合。

- **【修复】`ProfileLogic` 仍直连库**
  - 问题内容：仍用 `Db::name('dept')`，个人中心绕过数据权限。
  - 修复内容：迁移到模型查询。

- **【修复】数据规则 `sort` 字段不生效**
  - 问题内容：`sort` 不影响生效，但字段级动作按序处理，顺序实际取决于插入顺序。

  - 修复内容：删列。
