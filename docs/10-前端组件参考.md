## 一、`ArtTable` — 列表页核心表格

文件：`src/components/core/ArtTable.vue`

集成了搜索卡片、工具栏、表格、分页、列显隐、回收站模式的通用表格。

### 1.1 Props

| Prop | 类型 | 默认 | 说明 |
|------|------|------|------|
| `columns` | `ArtTableColumn[]` | 必填 | 列配置，见 [§十二](#十二类型-arttablecolumn) |
| `data` | `Record<string, any>[]` | 必填 | 表格数据 |
| `loading` | `boolean` | `false` | 加载中 |
| `total` | `number` | `0` | 总条数 |
| `rowKey` | `string` | `'id'` | 行 key |
| `height` | `number \| string` | `'100%'` | 表格高度 |
| `pageSizes` | `number[]` | `[10,15,30,50,100]` | 每页条数候选 |
| `selection` | `boolean` | `false` | 是否显示多选列 |
| `pagination` | `boolean` | `true` | 是否显示分页（树表常设 `false`） |
| `tree` | `boolean` | `false` | 树形表格 |
| `storageKey` | `string` | — | 列显隐持久化的 key（默认取当前路由 path） |
| `recycle` | `boolean` | `false` | 回收站模式 |

### 1.2 v-model

| 模型 | 默认 | 说明 |
|------|------|------|
| `page` | `1` | 当前页 |
| `limit` | `15` | 每页条数 |

### 1.3 Emits

| 事件 | 载荷 | 说明 |
|------|------|------|
| `refresh` | — | 点击刷新 |
| `search` | — | 提交搜索 |
| `reset` | — | 重置搜索 |
| `page-change` | `page` | 页码变化 |
| `size-change` | `limit` | 每页条数变化 |
| `sort-change` | `{ prop, order }` | 排序变化（列需 `sortable: 'custom'`） |
| `selection-change` | `rows` | 多选变化 |
| `restore` | `row?` | 回收站：还原（不传为批量） |
| `force-delete` | `row?` | 回收站：彻底删除（不传为批量） |

### 1.4 Slots

| 插槽 | 说明 |
|------|------|
| `search` | 搜索区内容（提供则渲染搜索卡片） |
| `toolbar` | 工具栏左侧 |
| `toolbar-right` | 工具栏右侧（放新增按钮、`RecycleToggle`） |
| `pager-left` | 分页左侧 |
| 列 `col.slot` | 自定义列渲染，作用域 `{ row, index, value }` |

### 1.5 特性

- 列显隐按页面持久化：`localStorage['cccms_table_hidden:{storageId}']`。
- **列宽拖拽记忆**：拖动表头后按页面持久化到 `localStorage['cccms_table_width:{storageId}']`；
  已保存的宽度**优先于**页面声明的 `width`（用户意图优先）；「列设置 → 重置」会同时清掉列宽。
- 用可见列指纹作 `:key` 强制重挂载表格（解决列设置后布局不刷新）。
- **回收站模式**：工具栏左侧换成「回收站模式」标签 + 还原 / 彻底删除按钮（`v-auth` 校验 `cccms:recycle:restore` / `cccms:recycle:delete`）；`slot: 'action'` 列被统一替换为操作列；搜索区不渲染。
- 响应式分页：窄屏自动切换为 `prev, pager, next`。
- 刻意**不开** `reserve-selection`（避免跨刷新残留脏勾选）。

> 列宽持久化由组件内部处理（监听 el-table 的 `header-dragend`），页面无需任何额外代码。

## 九、`useTable` — 列表页通用逻辑

文件：`src/composables/useTable.ts`

```ts
interface UseTableOptions<T, Q extends object> {
  api: (params: Record<string, unknown>) => Promise<PageResult<unknown>>
  initialQuery?: Q
  pageSize?: number       // 默认取后台配置 ui.page_size
  immediate?: boolean     // 默认 true，setup 阶段立即加载
  transform?: (list: T[]) => T[]
}

function useTable<T, Q extends object>(options: UseTableOptions<T, Q>)
```

返回值：

| 返回 | 说明 |
|------|------|
| `list` | 列表数据 |
| `loading` | 加载状态（**至少可见 300ms**，避免一闪而过） |
| `total` / `page` / `limit` | 分页 |
| `query` | 查询条件对象（响应式） |
| `selection` | 当前勾选行 |
| `load()` | 加载（参数为 `{ ...query, page, limit }`） |
| `search()` | 重置到第 1 页再加载 |
| `reset()` | 恢复 `initialQuery` 并回第 1 页 |
| `onPageChange` / `onLimitChange` | 分页事件处理 |
| `onSelectionChange` | 多选变化处理 |

**筛选方案持久化（页面零配置）**：

- 条件（含 `limit`，不含 `page`）一变就自动写入 `localStorage['cccms_table_filter:{storageId}']`；下次进入同页面**自动回填**（不自动提交，避免误触发请求）。
- 命名方案整体存 `localStorage['cccms_table_filter_scheme:{storageId}']`；`storageId` 默认取当前路由 path，可经 `storageKey` 覆盖。
- 回填只保留 `initialQuery` 声明过的字段（白名单），避免旧版本遗留字段被重新发给接口；页面未声明 `initialQuery` 时退化为原样回填。
- 这些能力**不经 `useTable` 返回值暴露**，而是通过 `provide(TABLE_FILTER_KEY, …)` 供 `ArtTable` 工具栏的「筛选方案」入口消费：

| 上下文成员 | 说明 |
|------|------|
| `key` | 当前页面的 storageId |
| `hasSaved()` | 是否存在上次保存的条件（决定是否显示「清空记忆」） |
| `clearSaved()` | 清空自动记忆的条件 |
| `listSchemes()` | 已保存方案名列表（`string[]`） |
| `saveScheme(name)` | 以 `name` 保存当前条件（同名覆盖） |
| `applyScheme(name)` | 应用方案（回填并回到第 1 页重新加载） |
| `removeScheme(name)` | 删除方案 |

## 十、`useRecycle` — 回收站

文件：`src/composables/useRecycle.ts`

```ts
interface RecycleOptions {
  reload: () => void       // 切换模式 / 操作完成后重新加载
  ids?: () => number[]     // 批量操作用的当前勾选 id
  clear?: () => void       // 清空勾选
}

function useRecycle(type: string, options: RecycleOptions)
// → { recycle, toggle, onRestore, onForceDelete }
```

- `type` 是后端 `RecycleLogic` 注册表里的类型（`user` / `role` / `dept` / `post` / `dict_type` / `dict_data` / `category` / `crontab` / `data_rule` / `file` / `menu`）。
- `onRestore(row?)` / `onForceDelete(row?)`：不传 `row` 用 `ids?.()`（批量），传 `row` 用其 id；均二次确认后调接口，再 `clear` + `reload`。

> ⚠️ **必须在 `useTable` 之前调用**（列表闭包在 setup 阶段就会执行一次）。三处接线见 [07-功能模块 §十六](07-功能模块.md#十六回收站recycle)。

## 十一、指令与工具

### 11.1 `v-auth`

文件：`src/directives/index.ts`（`setupDirectives(app)` 注册）

```vue
<el-button v-auth="'cccms:user:save'">新增</el-button>
<el-button v-auth="['cccms:recycle:restore', 'cccms:recycle:delete']">回收站</el-button>
```

- 不通过时 `display: none`（不移除 DOM）。
- 判断依据 `userStore.hasAuth()`：超管直通，普通用户命中任一即通过。

### 11.2 `downloadFile`（`api/request.ts`）

| 方法 | 说明 |
|------|------|
| `downloadFile(url, params?, fallbackName?)` | 拉取后端文件流并触发浏览器下载；复用同一 axios 实例（鉴权头 / 401 处理 / 进度条），文件名取 `Content-Disposition`（支持 RFC 5987 的 `filename*`） |

```ts
import { downloadFile } from '@/api/request'
await downloadFile('/log/export', { username: 'admin' }, '操作日志.csv')
```

> 约定：导出接口返回**文件流**而非统一信封。响应拦截器对 `responseType === 'blob'` 的请求
> 保留完整响应，其余请求仍按 `code === 0` 解包 `data`。

export interface ArtTableColumn {
