# 安装部署

> 本文覆盖：环境要求 → 后端安装 → 数据库初始化 → 启动 → 前端安装 → Docker → 生产部署 → 升级。按顺序执行即可从零跑通。

---

## 一、环境要求

| 项 | 要求 | 说明 |
|----|------|------|
| PHP | >= 8.1（推荐 8.3） | 必须启用 `pdo`、`pdo_mysql`、`pcntl`；建议 `redis`、`event` |
| MySQL | >= 8.0 | InnoDB，字符集 `utf8mb4` |
| Redis | >= 5.0 | 验证码、登录限流、配置缓存、会话分界线 |
| Node.js | >= 18 | 仅前端构建需要 |
| Composer | 2.x | 后端依赖 |

### 1.1 扩展说明

- **`pcntl`**：定时任务调度进程需要（仅 Linux / macOS 生效）。
- **`redis`**：装了 phpredis 扩展则使用扩展，否则自动回退纯 PHP 的 `predis/predis`（见 `server/config/redis.php`）。
- **`event`**：可选，提升 Webman 事件循环性能。

> ⚠️ **注意**：Windows 下 Webman 无法运行自定义进程（`pcntl` 不可用），因此**定时任务调度进程在 Windows 不生效**。开发环境如需要，请在 Linux / WSL / Docker 中运行。

## 二、后端安装

### 2.1 安装依赖

```bash
cd server
composer install
```

### 2.2 创建数据库并导入

自行创建数据库（字符集 `utf8mb4`），然后导入两份脚本：

```bash
# 1) 建库
mysql -uroot -p -e "CREATE DATABASE cccms DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 2) 核心表结构（20 张表）
mysql -uroot -p cccms < plugin/cccms/db/schema.sql

# 3) 初始化种子（超管角色、admin 账号、受控表登记、系统配置默认值）
mysql -uroot -p cccms < plugin/cccms/db/seed.sql
```

`seed.sql` 全部使用 `INSERT IGNORE`，**可重复执行**，升级时直接再跑一遍不会破坏已有数据。

### 2.3 配置数据库与密钥

数据库连接位于 `server/plugin/cccms/config/database.php`，支持环境变量覆盖：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `DB_HOST` | `127.0.0.1` | 数据库地址 |
| `DB_DATABASE` | `cccms` | 库名 |
| `DB_USERNAME` | `root` | 用户名 |
| `DB_PASSWORD` | `123456` | 密码 |
| `DB_PORT` | `3306` | 端口 |
| `DB_DEBUG` | `false` | 是否输出 SQL 调试信息 |

密钥位于 `server/plugin/cccms/config/auth.php`：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `JWT_SECRET` | 内置开发密钥 | **生产环境务必替换**；HS256 要求 >= 32 字节 |
| `DATA_ENCRYPT_KEY` | 内置开发密钥 | 字段级 `encrypt` 动作的 AES-256-GCM 种子；**一旦更换，历史加密字段无法解密（不做密钥轮换）** |

推荐用 `.env` 或部署平台注入，不要写进代码。

### 2.4 同步菜单与权限节点

```bash
cd server

php webman cccms:menu-sync      # 同步 db/menu.php 的目录 / 菜单（type=1/2）
php webman cccms:perm-scan      # 扫描控制器注解，生成按钮节点（type=3）
php webman cccms:db-upgrade     # 已有库补新增表 / 列 / 索引（全新装的环境可跳过，幂等可重复执行）
```

> **为什么需要这两步**：菜单（目录 / 菜单）由 `db/menu.php` 声明，按钮节点由控制器注解生成。二者都会写入 `sys_menu`，是权限体系的数据来源。

### 2.5 启动

```bash
# Windows（不启用定时任务进程）
php windows.php

# Linux / macOS
php start.php start        # 前台运行，调试用
php start.php start -d     # 后台守护运行
php start.php status       # 查看状态
php start.php reload       # 平滑重载（改代码后）
php start.php stop         # 停止
```

默认监听 `http://0.0.0.0:8787`（见 `server/config/process.php`）。

快速自检：

```bash
curl http://127.0.0.1:8787/ping
# {"code":0,"message":"ok","data":{"pong":true,"time":...}}
```

### 2.6 默认账号

| 账号 | 密码 | 说明 |
|------|------|------|
| `admin` | `admin123` | 内置超管，**首次登录后请立即修改密码** |

## 三、前端安装

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
npm run build      # 产物在 dist/
npm run preview    # 本地预览构建产物
```

### 3.1 接口代理

开发期前端统一以 `/api` 前缀调用接口，由 Vite 代理到后端（`frontend/vite.config.ts`）：

```
/api/xxx  →  http://127.0.0.1:8787/xxx   （转发时去掉 /api）
```

接口基地址通过环境变量 `VITE_API_BASE`（默认 `/api`）配置，见 `frontend/.env.development` / `.env.production`。

### 3.2 生产环境部署前端

```bash
npm run build
# 将 dist/ 交给 Nginx 托管，并把 /api 反向代理到后端 8787
```

> ⚠️ **注意**：前端使用 **hash 路由**（`createWebHashHistory`），Nginx 不需要额外的 `try_files` 兜底；访问形如 `https://your.domain/#/cccms/user`。

## 四、Docker 部署

`server/` 下提供了 `Dockerfile` 与 `docker-compose.yml`：

```bash
cd server
docker compose up -d --build
```

- 镜像基于 `php:8.3-cli-alpine`，启用了 `pdo_mysql` / `pcntl` / `opcache`。
- `docker-compose.yml` 把当前目录挂载到容器 `/app`，暴露 `8787` 端口，启动命令为 `php start.php start`。

> `docker-compose.yml` 只编排了 Webman 一个服务，**未包含 MySQL 与 Redis**。请在 `docker-compose.yml` 中补充 `mysql` / `redis` 服务，或将 `DB_HOST` / Redis 地址指向已有实例。

## 五、生产部署清单

### 5.1 后端

1. **关闭 debug**：`server/config/app.php` 的 `debug` 目前为 `true`，生产必须改为 `false`（否则异常信息会透出）。
2. **替换密钥**：注入 `JWT_SECRET` 与 `DATA_ENCRYPT_KEY`（随机、足够长）。
3. **数据库账号**：使用最小权限账号，不要用 `root`。
4. **进程守护**：推荐 supervisor 或 systemd 管理 `php start.php start`，并配置自动重启。
5. **目录权限**：`server/runtime` 需可写；`server/public/storage` 需可写。
6. **Web 服务器**：Nginx 反向代理到 `127.0.0.1:8787`，静态资源（`/storage/*`）可直接由 Nginx 托管。

### 5.2 `public/storage` 安全（硬要求）

**必须禁止在上传目录解析 PHP**，否则同域上传目录可执行脚本 = 任意代码执行。

Nginx 示例：

```nginx
location ^~ /storage/ {
    deny all;                     # 若由后端 /storage 逻辑分发，则拒绝直接访问
}

# 若由 Nginx 直接托管上传文件：
location ^~ /storage/ {
    location ~ \.(php|php5|phtml|phar)$ { deny all; }
}
```

> **建议**：把附件切到独立域名 / CDN（`upload.url_prefix` 或云存储驱动），从根上隔离上传目录与主站。

### 5.3 前端

```nginx
server {
    listen 80;
    server_name your.domain;
    root /var/www/cccms/frontend/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8787/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / { try_files $uri $uri/ /index.html; }
}
```

### 5.4 首次上线后

1. 用 `admin / admin123` 登录并**立即改密**。
2. 「系统设置 → 配置管理」按需调整品牌、界面、安全、上传、日志配置。
3. 按需在「权限配置 → 数据权限 → 受控表」登记业务表。
4. 配置定时任务（如日志清理 `DemoTask`）。

## 六、升级

代码更新后：

```bash
cd server
composer install                 # 依赖有变时
php webman cccms:db-upgrade      # 幂等补表/列/索引，并执行各业务插件的 schema
php webman cccms:menu-sync       # 同步菜单声明变化
php webman cccms:perm-scan       # 同步按钮节点变化
php start.php reload             # 平滑重载

cd ../frontend && npm install && npm run build
```

> 后台顶栏「系统同步 / 清理缓存」按钮提供与 CLI **共用同一份实现**的图形入口（范围：`all` / `menu` / `perm` / `schema` / `cache`），适合日常小改动后刷新。

## 七、安装常见问题

| 现象 | 原因 / 处理 |
|------|-------------|
| 启动报 `Class "Redis" not found` | 未装 phpredis 扩展且未安装 predis 依赖；`composer install` 会装 `predis/predis`，或安装 phpredis 扩展 |
| 报「接口未声明权限」500 | 新增控制器方法没写权限注解（fail-closed 生效），补 `#[Permission]` / `#[NoAuth]`，见 [05-鉴权与权限](05-鉴权与权限.md) |
| 菜单 / 按钮看不到 | 未执行 `menu-sync` / `perm-scan`，或当前角色未授权该节点 |
| 列表接口报「列不存在」 | 模型参与数据权限但表中没有对应归属列，需要在模型里声明语义或 `$dataScope = false`，见 [06-数据权限](06-数据权限.md) |
| 定时任务不执行 | Windows 不支持自定义进程；Linux 确认 `php start.php status` 中 `crontab` 进程在运行 |

更多排错见 [12-常见问题与排错](12-常见问题与排错.md)。
