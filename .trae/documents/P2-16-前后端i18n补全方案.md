# P2-16 前后端 i18n 补全方案（M9 · 效率与体验）

## 一、背景与目标

M9 已交付 P2-1 / P2-2 / P2-5 / P2-6 / P2-8 / P2-15，仅剩 **P2-16**。原计划只覆盖前端，用户明确扩大范围：

- 前端：业务页硬编码中文文案迁移到 `t('...')`。
- 后端：**页面标题、菜单标题、校验/错误提示、系统配置项名**也要 i18n。
- **用户录入的业务数据不做 i18n**（通知标题、字典项名、管理员自建菜单、配置项「值」等）。

现状事实（已核实）：

| 项 | 现状 |
|----|------|

| 前端语言包 | 单文件 `src/locales/{zh-CN,en-US}.ts`，仅 6 个命名空间（common/layout/login/error/table/setting） |
| 菜单/节点标题 | 同表 `sys_menu`（type=1 目录 / 2 菜单 / 3 按钮），标题来自 `server/plugin/cccms/db/menu.php` 与控制器 `#[Permission(title:)]`，由 `menu-sync` / `perm-scan` 写入 DB |

## 二、已确认的四项决策

1. **菜单/节点标题**：后端按 `slug` 覆盖返回。DB 的 `title` 保持中文作为权威兜底；新增 `lang/{locale}/menu.php`（slug → 标题），`MenuLogic` 返回前按当前语言覆盖。未登记的 slug（管理员自建菜单）= 用户数据，原样返回。**零 schema 变更**。
2. **前端语言包**：按模块拆目录 `src/locales/{zh-CN,en-US}/`，每命名空间一个文件，`index.ts` 聚合。
3. **后端提示语范围**：只迁 **用户可见层**（`app/logic/`、`app/controller/`、`app/middleware/`，约 90 处）；`support/` 下工具类断言保持中文（避免工具类依赖请求上下文）。
4. **交付节奏**：分两批。本轮交「基础设施 + 后端 + 高频页」。

## 三、后端实施方案

### 3.1 `I18n::has()`（新增能力）

`server/plugin/cccms/support/I18n.php` 增加：

```php
/** key 是否存在（不写 missing 日志、不返回 key 原文），供「有翻译才覆盖」的场景使用 */
public static function has(string $key): bool
{
    $locale = self::locale();
    if (self::lookup($locale, $key) !== null) {
        return true;
    }
    return $locale !== self::DEFAULT_LOCALE && self::lookup(self::DEFAULT_LOCALE, $key) !== null;
}
```

复用现有 private `lookup()` 与 `loadNamespace()` 缓存，不重复实现。

### 3.2 语言包文件

`server/plugin/cccms/lang/{zh-CN,en-US}/` 下新增：

| 文件 | 内容 | key 约定 |
|------|------|----------|
| `menu.php` | 菜单 / 目录 / 按钮节点标题 | `menu.{slug}`，如 `menu.cccms:user`、`menu.cccms:user:batch_status` |
| `config_item.php` | 内置配置项展示名 + 分组展示名 | `config_item.{name}`（如 `config_item.system.name`）、`config_item.group.{group}` |
| 各模块提示语 | `user.php` / `role.php` / `dept.php` / `post.php` / `dict.php` / `config.php` / `file.php` / `log.php` / `notice.php` / `crontab.php` / `data_rule.php` / `profile.php` / `online.php` / `category.php` / `generator.php` / `upgrade.php` / `maintenance.php` / `menu.php`（菜单模块提示语与标题同文件、key 不冲突） | `{模块}.{语义}`，如 `user.cannot_delete_self` |

`menu.php` 的 106 条（16 个目录/菜单 + 90 个按钮节点）用**一次性脚本**从 `db/menu.php` 与控制器 `#[Permission]` 注解生成，生成后删除脚本；英文标题按既有术语表人工校对。

### 3.3 接线点

- `MenuLogic::tree()` / `MenuLogic::userTree()`：新增私有 `localizeTitles(array $rows): array`，对每行 `I18n::has('menu.' . $row['node'])` 为真时覆盖 `title`。两个方法在 return 前各调一次。
- `ConfigLogic::list()`：`title` 用 `config_item.{name}` 覆盖；**新增 `group_label` 字段**（`config_item.group.{group}`）承载翻译后的分组名，**`group` 原样返回**（前端用它做 `?group=` 过滤值，不能改）。
- 用户可见层的 `throw new ApiException('中文')` / `throw new \RuntimeException('中文')` → `I18n::t('{模块}.{key}')`。含 `MenuLogic.php:103,112`（菜单管理页可见）。
- `support/` 层（`Cipher`、`TokenService`、`storage/*`、`SqlFileRunner`、`Upgrader`、`LogArchiver`、`PasswordPolicy`、`Csv`、`MenuSyncer`）**不改**。

### 3.4 新增测试

`server/tests/cases/I18nTest.php`（零依赖，返回注册闭包）：

1. `I18n::has()` 命中已存在 key、未命中不存在 key。
2. **两语言包 key 集合一致**：递归比对 `lang/zh-CN/*.php` 与 `lang/en-US/*.php` 的文件名集合与每个文件的 key 集合（防漏翻的核心守卫）。
3. **`menu.php` 覆盖完整**：`db/menu.php` 声明的全部 slug（含 children）都在 `lang/*/menu.php` 里。

## 四、前端实施方案

### 4.1 语言包拆目录

```
src/locales/
  index.ts          # createI18n + currentLocale + setLocale（保持现有导出不变）
  title.ts          # translateTitle() 助手
  zh-CN/index.ts    # 聚合各命名空间
  zh-CN/{common,layout,login,error,table,setting,route,menu,user,role,dept,post,dict,config,file,log,notice,crontab,dataRule,profile,online,category,generator,upgrade,dashboard}.ts
  en-US/            # 同构
```

- 现有 6 个命名空间内容**原样搬迁**，不改变 key。
- 新增 `route.ts`：静态路由标题 `login` / `dashboard` / `profile` / `forbidden` / `notFound`。
- 删除原 `src/locales/{zh-CN,en-US}.ts`，`index.ts` 改为 `import zhCN from './zh-CN'`。

### 4.2 标题翻译助手

`src/locales/title.ts`：

```ts
/**
 * 标题翻译：值是 i18n key 就翻译，否则原样返回。
 * 后端已按 Accept-Language 本地化过的菜单标题、管理员自建菜单标题都走「原样返回」。
 */
export function translateTitle(raw: unknown): string {
  const text = raw == null ? '' : String(raw)
  if (text === '') return ''
  return i18n.global.te(text) ? String(i18n.global.t(text)) : text
}
```

在模板 / computed 中调用即可跟随 `setLocale()` 响应式更新（内部走 `i18n.global.t`）。

### 4.3 接线点

| 文件 | 改动 |
|------|------|

### 4.4 一致性校验脚本

`frontend/scripts/check-i18n.mjs`（Node ESM，零新依赖，用 `esbuild` 编译 TS 语言包后比对）：

1. **key 集合一致性**：`zh-CN` 与 `en-US` 的命名空间文件集合 + 每个文件的 key 集合必须完全一致，不一致打印差异并 `exit 1`。
2. **硬编码中文报告**：扫描 `src/pages/**/*.vue` 与 `src/layouts/**`，统计中文字面量数量并按文件输出（**本轮 informational，不 fail**；批次二清零后改为 fail）。

`package.json` 新增 `"i18n:check": "node scripts/check-i18n.mjs"`；`.github/workflows/frontend.yml` 增加一步 `npm run i18n:check`。

### 4.5 本轮迁移的页面（批次一，10 页）

`user`、`role`、`dept`、`post`、`dict`、`config`、`menu`、`log`、`profile`、`online`。

迁移模式（每页一致）：

- 表格 `columns` 的 `label`、表单 `label` / `placeholder`、按钮文案、`ElMessage` / `ElMessageBox` 文案、抽屉/弹窗标题 → `t('{模块}.{key}')`。
- 枚举/状态映射（如 `status: 1 → '启用'`）改为返回 i18n key，渲染处 `t()`。
- **不翻译**：用户录入数据的展示（通知标题、字典项名、配置项「值」、日志内容、菜单标题由后端处理）。

**批次二（下一轮）**：`data_rule`、`crontab`、`file`、`notice`、`generator`、`upgrade`、`dashboard`。
